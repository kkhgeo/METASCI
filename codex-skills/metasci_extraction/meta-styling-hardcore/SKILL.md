# Meta-Styling · Hardcore (brick assembly)

An experiment, and labelled as one in every report. `meta-styling` asks, edit by edit,
whether a corpus habit fits the draft. This skill does not ask. Every draft sentence that
*can* be rebuilt on a corpus frame *is* rebuilt on one, and the result shows what the
corpus does to the draft when it is applied without judgment.

The mechanism is taken from a "brick" composition method: **pick bricks by their number,
let code put the text together from those numbers, never retype a sentence.** Because the
model writes IDs instead of prose, it cannot paraphrase, smooth, or slip in its own
phrasing. Every word of the output is a corpus word, a draft word, or a counted piece of
mortar.

## Bricks

| Brick | ID | Comes from | Carries |
|---|---|---|---|
| Frame | `F###` | `logic.md` §E catalog, *Abstracted Template* column, target section only | the corpus's sentence skeleton — its fixed words are the style being imposed |
| Bundle | `B###` | `phrases.tsv`, `bundle = yes`, `topic = no`, occurring in the target section | recurrent multi-word glue the corpus actually uses |
| Content | `C#` | the draft, cut by the model into verbatim spans | the draft's substance: values, entities, propositions, with their citations |
| Draft sentence | `D#` | the draft, numbered by the script | used only through `keep`, counted as not imposed |
| Corpus sentence | `S###` | `logic.md` §E *Original Sentence* | only with `--unit sentence`; see below |

Mortar is everything else, and all of it is counted: glue words from a frozen list, at
most three `[YOU WRITE: …]` gaps, `pick` among a template's own alternatives
(`was/were`), `inflect` for number agreement only, and automatic spacing, `a`/`an`,
capitalisation and terminal periods.

### The brick unit: frame by default

The default unit is the **frame**, not the sentence. Lifting whole sentences from
reference papers would copy another author's wording (plagiarism, and text recycling
even for one's own papers), and each lifted sentence carries that paper's values and
claims into the draft. Frames carry the skeleton and leave the substance to the draft.

To switch, build the pile with `--unit sentence` and verify with `--own-corpus`. That is
the original brick method — recomposing text from one's own published sentences — and it
is allowed only when the user states that the corpus is their own papers. In that mode
content drift is expected; Gate 1 reports it and the report says so.

## The rules, translated

The brick method was written for short popular prose. Each rule has an academic
counterpart; the right-hand column says who enforces it.

| Brick rule | Here | Enforced by |
|---|---|---|
| Pick bricks by number; code assembles; never retype | `plan.json` names IDs; `brickyard.py assemble` builds `revision.txt` | script (verify fails on any hand edit) |
| Open on the most surprising brick | Open each paragraph on a frame that opened a paragraph in its source paper (`pos = initial`) | model; verify reports misses |
| Keep one idea, skip drifting bricks | The draft's content is fixed: every content brick is a verbatim draft span, nothing else enters | script (spans) + Gate 1 + Gate 2 |
| Bricks from ≥ 4 articles | Frames from at least min(N, 3) papers of the pile | model; verify reports |
| 2–4 bricks in a row from one article, in order | Borrow a paper's sentence-role chain: 2–4 consecutive frames from one paper in source order | model; verify counts runs |
| End on a closing brick or a gap | End each paragraph on a frame that closed a paragraph in its source (`pos = final`) or on a gap | model; verify reports |
| Match the reader | Frames from the draft's own section only (I, M, R, D, C) | script (`--cross-section` to lift) |
| Length within 10 % | Within ±15 % of the draft | verify warns |
| Nothing between bricks | Only bricks, frozen glue, ≤ 3 one-line gaps; glue ≤ 15 % of words | script |
| Check with code; swap a brick that makes the reader stop | `brickyard.py verify`, then Gates 1–2, then a reader pass that swaps bricks in the plan | script + model |

## Inputs

1. **Draft and its section.** English manuscript prose. Prepare `0-draft.prose.txt` the
   way `meta-styling` guide §1 does: prose only, no notes, no headings, paragraphs
   separated by blank lines.
2. **Corpus root.** An `extraction-style` v3.x corpus. Frames need `logic.md`; bundles
   need the 3.1 `phrases.tsv`. Resolve it as `meta-styling` does (given path →
   `*style*corpus*` / `Style_*` folder → ask). Never build one here.
3. **Optional**: a subset of papers; `--unit sentence` with the user's statement that
   the corpus is their own work.

## How a run works

Run folder: `<draft-dir>/run/<draft-stem>/<run-id>-hardcore/`. `<skill>` below is this
skill's folder. Use `python`, `python3` or `py -3`, whichever exists.

**1. Scope.** Announce draft, section, corpus, papers, brick unit, and that the run is
experimental.

**2. Pile.**

```text
python "<skill>/scripts/brickyard.py" pile --corpus <corpus> --section R --draft 0-draft.prose.txt --out pile [--papers a,b] [--unit sentence]
```

Exit 2 means no frames for that section: check the section letter, or ask before using
`--cross-section`. Read `pile/form.tsv` (the frames and bundles) and `pile/draft.tsv`.

**3. Cut the content.** Write `pile/content.tsv` per `references/plan-format.md`, then
`brickyard.py content --pile pile`. Every span must pass.

**4. Plan.** Write `plan.json`. For each draft sentence:

- **If any frame in the pile can host its content bricks, use one.** Awkwardness is not a
  reason to skip; it is the data the experiment collects. Only when no frame's slots can
  take the content does the sentence become `{"keep": "D#"}`.
- A draft sentence may be split over two frames, and two may be merged into one, provided
  every content brick lands somewhere.
- Apply the ordering rules from the table: opener frame first, a closer or gap last,
  runs of 2–4 frames from one paper in source order, frames from at least min(N, 3)
  papers.
- A gap is for a connective move that the frame chain needs and no brick supplies. Never
  use a gap to carry content, and never more than three.
- `pick` and `inflect` only to make the template agree with its content.

**5. Assemble.**

```text
python "<skill>/scripts/brickyard.py" assemble --pile pile --plan plan.json --out revision.txt --trace trace.tsv
```

Errors write nothing. Fix the plan, never the text.

**6. Check.** All three, in order:

```text
python "<skill>/scripts/brickyard.py" verify --pile pile --plan plan.json --revision revision.txt --report verify.md [--own-corpus] [--strict]
python "<meta-styling>/scripts/preservation_inventory.py" --before 0-draft.prose.txt --after revision.txt --citation-style <author-year|numeric|none> --output inventory.tsv [--terms terms.txt]
```

then Gate 2, sentence by sentence, as `meta-styling` guide §6 defines it. Then read the
revision once as a reviewer of the target journal would: where a sentence makes that
reader stop, **swap a brick** (another frame, another cut, another pick) in the plan and
go back to step 5. At most three swap rounds; what still stops the reader is reported as
a finding, not fixed by hand.

**7. Report** (user's language; see Output).

## Rules that do not bend

- **Never retype.** `revision.txt` is only ever written by `assemble`. `verify`
  re-assembles the plan and fails on any difference, and rebuilds the pile from the
  corpus and fails if `form.tsv` was altered.
- **Substance comes only from the draft.** Content bricks are verbatim draft spans. A
  frame's fixed words may change the framing verb or connective; if they change a claim's
  certainty, polarity or causal meaning, Gate 2 fails and the brick is swapped.
- **Domain words never travel.** Topic-bound bundles are excluded by the script. If a
  frame's fixed words name the reference paper's subject (`nitrate`, a site name), that
  frame is not usable for this draft; choose another.
- **No long corpus runs.** `verify` fails any sentence that repeats 8 or more consecutive
  corpus words the draft did not already contain (`--copy-limit`), unless `--own-corpus`.
- **Gates are not relabelled.** A Gate 1 FAIL stays FAIL. The revision is then reported
  as an experimental result, not recommended for the manuscript.
- **The user's rules beat the corpus**, as in `meta-styling`. A frame that violates a
  stated rule is not used.

## Output

In the user's language, in this order:

1. Scope: N, papers, section, brick unit, "experimental".
2. Imposition summary lifted from `verify.md`: sentences built on frames, keeps, gaps,
   papers used, same-paper runs, opener/closer hits, singleton frames used, word sources
   (frame / bundle / content / glue).
3. The complete revision, exactly as `revision.txt`.
4. Findings: which draft sentences took no frame and why; where forced frames broke
   meaning or read badly after three swap rounds; any Gate 1 notation re-parses.
5. Gate results: brickyard verify, Gate 1, Gate 2, with what was inspected.

Offer, in one line, a normal `meta-styling` run as the follow-up when the user wants a
manuscript-ready revision.

## Gotchas

- **Most frames are singletons.** extraction-style measured 190 of 193 frames occurring
  once in their paper. A frame's *skeleton* is reused here, not its anchor wording, but
  every singleton used is listed in the report. A pile whose `status` column reads
  `unmeasured` has no recurrence data; say so.
- **Range notation re-parses in Gate 1.** `between 12 and 40 mg/L` rebuilt on
  `ranged from [MIN] to [MAX]` becomes the range key `12to40` and Gate 1 FAILs although
  the values are intact (seen on the test corpus). Either cut the range as one content
  brick, or report the FAIL as a notation change; never relabel it.
- **Glue share is the honesty meter.** If the frames do not fit, the plan drifts towards
  glue words and bundles. Above 15 % `verify` fails: the frames are not carrying the
  text.
- **Templates with choice tokens** (`was/were`) default to the first alternative when not
  picked; the warning names them. Pick explicitly.
- **`logic.md` table layouts vary.** The parser reads any table whose header has a
  *Template* column and takes the section from the nearest heading, falling back to a
  search of `sections/*.txt` for the original sentence. Check `form.tsv`'s `section` and
  `pos` columns before planning; rows without `[P#-S#]` get `pos = unknown`.
- The sentence splitter protects `et al.`, `Fig.`, `e.g.`, decimals. A draft with other
  abbreviations may split wrongly in `draft.tsv`; that affects `keep` only.

## Error handling

| Situation | Response |
|---|---|
| No corpus, or several | As `meta-styling`: ask; never build one |
| `pile` exit 2 | No frames for the section; check the letter or ask about `--cross-section` |
| A content span fails | Re-cut it verbatim; never normalise the draft to match |
| `assemble` errors | Fix the plan; nothing was written |
| `verify` FAIL on hand edit or pile tampering | Re-assemble or rebuild the pile; never patch the text |
| `verify` FAIL on copy run | Swap that frame; only `--own-corpus` (user's statement) turns it into a warning |
| Gate 1 FAIL | Swap bricks until it passes, or report the FAIL and do not recommend the text |
| Korean draft | Stop; point to `meta-rewriting-korean` |
