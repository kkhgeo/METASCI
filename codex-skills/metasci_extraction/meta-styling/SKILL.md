# Meta-Styling

Revise an English academic draft so that its structure and wording follow a style corpus
that `extraction-style` has already built from reference papers. The corpus is the
evidence; the draft's meaning is fixed. A difference from a reference is an observation,
and it becomes an edit only when it fits the draft's function, its existing content, and
the user's rules.

The default output is one recommended revision with a short report. Alternatives are
offered when the user asks for a comparison or when two supported choices genuinely differ.

This skill asks whether the draft's structure and wording match the selected references.
It does not judge whether the argument is good.

## Inputs

1. **Draft and its section** (Introduction, Methods, Results, Discussion, Conclusions, or a
   report chapter). A working document with notes, ledgers, or a translation mirror is
   normal; only the manuscript prose is measured and revised (guide §1). If the draft
   carries its own style rules, they win over the corpus.
2. **Corpus root** — an `extraction-style` v3.x folder:

```text
<corpus-root>/
├── index.md                    optional
├── style_profile.md            optional cache; verify scope and provenance before reuse
└── papers/<slug>/
    ├── card.md                 selected findings and Red Flags
    ├── logic.md                paragraph functions, sentence roles, frames (§C–§F)
    ├── style-vocab.md          reporting verbs, hedges, connectives by section (§C–§D)
    ├── anchors.txt             one anchor phrase per line, for counting only
    ├── manifest.json           section scheme, measured rows, provenance
    └── sections/*.txt          counting basis (never body.txt)
```

   Resolve in this order: the path the user gave → a folder matching `*style*corpus*` or
   `Style_*` at or under the working directory → ask. If more than one corpus is found,
   list them and ask; corpora are not interchangeable. If none exists, say that
   `extraction-style` builds one; do not start extraction and do not substitute another
   collection.

Use cached measurements only when the selected papers, target section, counting basis,
and source versions match the current run. A recent modification date alone does not
establish validity. Missing or incompatible caches do not block use of the corpus.

3. **Optional**: a subset of paper slugs; a request for alternative versions.

Check the language of the extracted prose, not the raw file. English prose with Korean
notes is in scope. Prose meant to stay Korean goes to `meta-rewriting-korean`.

## How a run works

Each run lives in `<draft-dir>/run/<draft-stem>/<run-id>/` and leaves
`0-draft.prose.txt` (the prose in scope), `review-notes.md` (scope, draft map, evidence,
decisions, gate results), `revision.txt` (manuscript prose only), and `inventory.tsv`
(Gate 1 output). The guide has the details; the sequence is:

1. Establish scope, corpus, N, and the user's rules; announce them (guide §1).
2. Tag the draft — paragraph functions, sentence roles, frame codes — **before** opening
   reference findings (§2).
3. Read the pointed sections of each paper's `logic.md` and `style-vocab.md`; record
   observations with addresses (§3).
4. Decide edit by edit: comparable function, applicable with existing content, within the
   user's rules (§4).
5. Write the revision (§5).
6. Run both preservation gates, then report (§6).

## Rules that do not bend

- **The user's instructions and the manuscript's explicit rules beat the corpus.** A
  conflicting corpus habit is recorded as an unapplied observation, never slipped into
  the revision.
- **Content is preserved, and two gates check it.** Gate 1 is mechanical: from the run
  folder, `python "<skill-dir>/scripts/preservation_inventory.py" --before
  0-draft.prose.txt --after revision.txt --citation-style <author-year|numeric|none>
  --output inventory.tsv` (exit 0 PASS, 1 FAIL, 2 BLOCKED; details in guide §6). Gate 2
  is a sentence-by-sentence meaning check. Both must PASS before a revision is
  recommended. A FAIL row may stand only as a `PASS WITH USER-AUTHORIZED EXCEPTION`
  recorded in the notes: the user authorized that exact change before grading, and no
  BLOCKED issue remains. Never relabel the script's output. Consolidating repeated
  references needs that authorization. Why: a measured run satisfied "Figure 2 → Fig. 2"
  by deleting the figure reference, and the wording check read clean.
- **Claim strength is substance.** Changing `proves` to `suggests`, or the reverse,
  changes the claim; it is not a style edit.
- **Nothing is invented.** Do not add a condition, mechanism, limitation, or decision to
  complete a reference's sentence chain. If it is needed and missing, say so outside the
  manuscript text.
- **Tag first, then compare.** Tagging a draft against a known target manufactures
  matches. Record whether isolation was by a separate worker context or by reading order.
  A follow-up on an already-compared draft is the one exception, and it is disclosed.
- **Evidence has a scope.** Always report N and the papers used. With N≤2, applied
  structural habits are labelled as choices observed in those papers, not as a norm. A
  measured zero is strong evidence of absence in the passage counted; a missing file or a
  failed search is not evidence. No metric bands and no hedge quotas.
- **Frame codes are fixed; function labels are not.** One primary A–L code per sentence,
  `Z` with a named shape for the rest. Paragraph-function and sentence-role labels may be
  extended.

## Output

The report is written in the user's language and contains, in this order: N, papers,
section mapping, and analysis method; the main edits with their evidence; the complete
recommended revision (or the original, if nothing was warranted); unapplied choices and
open questions; the two gate results and what was actually inspected. Preserved citations
are not thereby verified against their sources.

## Gotchas

- The language check on a raw working document can return `ko` when Korean notes surround an
  English manuscript. Check `0-draft.prose.txt`.
- `find*` does not match `found`. Inspect wildcard hits; a count does not tell a reporting
  verb from another use of the word.
- `body.txt` includes the abstract; counts use `sections/*.txt`.
- `anchors.txt` stores no Singleton/Recurrent status; `logic.md` §E.5 does.
- `logic.md` can be large. Read the sections the guide's table points to. Its exhaustive
  frame catalog does not imply exhaustive sentence-role analysis; role chains may cover
  only representative paragraphs. Treat unrecorded roles as unassessed.
- A roadmap sentence ("this paper is organized as follows") and a local signpost are
  different features; one card flags the first and uses the second.
- Never run counts or the inventory on a file that carries a metadata header; the digits
  in `EDIT-3` would be counted.

## Error handling

| Situation | Response |
|---|---|
| No corpus found | Ask for the path; explain that `extraction-style` builds one; never start it |
| Several corpora found | List them and ask |
| `style_profile.md` missing or stale | Normal; derive from cards and say so |
| Draft's section absent from the corpus scheme | Use an explicitly documented fusion (`manifest.prep.detection_notes` or a source heading) and disclose it; otherwise omit section-dependent judgments |
| `logic.md` missing for a paper | Use only lexical or absence observations actually supported by the remaining files; mark structural comparisons unassessed |
| Draft very short | Still do the qualitative comparison; skip only measurements that need length |
| Korean draft or corpus | Stop; point to `meta-rewriting-korean` |
| An edit would change a claim or its certainty | Not applied; explained in the report |
| Gate 1 FAIL | Restore unapproved changes and rerun; for previously authorized changes, retain raw FAIL and use the exact-row exception adjudication above |
| Gate 1 BLOCKED | Inspect the notation, extend the extractor with a regression example, and rerun; keep BLOCKED until resolved. Manual inspection does not replace the machine check |
| Isolated workers unavailable or not authorized | Run sequentially in the guide's order; record "isolation by ordering" |
