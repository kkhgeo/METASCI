# Meta-Rewriting — Four-Stage Paragraph Review & Rewrite

Work in four stages, in order: **입력 → 원리 로드 → 진단 → 대안**. The
stages exist because each one feeds the next: you cannot diagnose without
the principles in hand, and you cannot rewrite well without a diagnosis to
aim at. Do not skip ahead to rewriting.

**Language rule:** all commentary and diagnosis in Korean (한국어); every
rewritten paragraph is in **English**, whatever language the draft arrived
in. The user writes English manuscripts, so a Korean draft comes here to
leave as English prose — note that in ① when the source is Korean. Each
rewritten paragraph is followed by a **국문 번역** so the author can verify
at a glance that the rewrite still says what they meant. The translation is
a comprehension aid, not manuscript prose: the English text is the
deliverable, and the translation is checked against no Korean register
standard. A Korean paragraph that is meant to *stay* Korean does not belong
here: say so in one line and point to `meta-rewriting-korean`. This skill
carries no Korean register standard, and judging Korean prose by English
norms wrecks it.

**No fact-checking:** take the draft's data and citations as given. If
something looks factually suspect, one brief note in ② is enough; move on.

## Stage 1 — 입력 (Input)

Establish three things before any analysis: the paragraph, its section, and
nothing else.

- **The paragraph.** Pasted text → use as-is. File path (+ optional
  paragraph number) → Read the file, locate the paragraph, confirm the
  target in one line before proceeding.
- **One paragraph per response.** If the user pastes several, run the full
  output for the FIRST paragraph only and offer "다음 단락" in ⑤ — one
  paragraph per response keeps each review readable.
- **Section type.** The user normally states it ("Results 단락이야"). If
  they did not, and the text does not make it unmistakable, ask with one
  AskUserQuestion listing the section types (Abstract / Introduction /
  Methods / Results / Discussion / Conclusion / Literature Review /
  모름·해당 없음). Do not guess: a wrong section guess applies the wrong
  required-element checks, and silently skipping the section checks hides
  real defects. "모름·해당 없음" is the one case where the section block is
  legitimately skipped.

## Stage 2 — 원리 로드 (Load the principles)

Load the writing standards **before** diagnosing — the diagnosis in
Stage 3 is only as complete as the guidelines in front of you, and the
rewrites in Stage 4 are only as principled as what you loaded here. Two
mandatory reads:

**1. `references/section-checklists.md`** — the diagnostic checklist.
Apply in two tiers:

- *Always:* the section-independent blocks — 문장 스타일 공통 and
  인용·참고문헌 규범. These hold for any academic paragraph.
- *When the section is known* (stated, unmistakable, or answered in
  Stage 1): that section's own block, **in full, every item** — not a
  sample. Checking every item is the point of asking for the section.

**2. The writing manual, `references/manual/`** — the principle layer the
rewrites must *exemplify*, not merely avoid violating. Read
`00_universal.md` plus the one file matching the section
(`01_title_abstract` / `02_introduction` / `03_methods` / `04_results` /
`05_discussion` / `06_conclusion` / `07_references`) — never the whole
folder. `DECISIONS.md` there holds both sides of the venue-bound
questions below; open it only when one of them comes up. The folder is a
bundled copy of the standalone writing manual — `_SOURCE.md` records the
upstream and what was deliberately left out.

Three rules for using the manual: (a) **convergence counts measure how
often advice authors repeated an idea, not how mandatory it is** — never
rank findings by convergence; (b) entries flagged `[~] Verified with
drift` need re-quoting from the PDF before the user cites them; (c) where
the manual and this skill's `references/principles.md` overlap,
principles.md is more precise and takes precedence — the manual itself
records this.

These blocks are written for English prose, which is what this skill always
produces. When the draft is Korean, run 문장 스타일 공통 against the English
you write in ④ rather than against the Korean surface — contractions,
run-ons, and English clichés have no Korean counterpart, so applying them
to the Korean original produces false positives. The logic-level checks
(information flow, referents, argument soundness, citation norms) apply to
the draft either way: they are matters of inference, not English grammar.

**Know the principles' limits.** Three claims sound like principles but are
refuted or overreaching — applying them is over-correction, the one defect
the author has no way to see:

- ❌ *"Subject and verb must be as close as possible; intervening material
  of any length is a burden."* Refuted under verification — short
  interruptions cost the reader nothing. Flag long ones only.
- ❌ *"Add connectives to improve flow."* Cohesion is not coherence (Cooper
  1988): cohesive ties are surface devices, and adding them does not make
  an incoherent argument coherent. Repair the logic first, and add a
  connective only where the relation it names is already true.
- ❌ *"Correct the sentence to standard form."* Grammaticality is not
  communicative function (Kuo 1995): two equally grammatical sentences
  carry different value depending on placement and information structure.
  Judge a sentence in its discourse context, not by grammar in isolation.

**Venue-bound questions — ask, never default.** Abstract length, title
length, and abstract voice are settled by the target journal, not by
evidence. If the paragraph turns on one, ask (target journal, field
convention), then say which convention you applied. Two related questions
ARE settled and are stated as decisions, not options: **first person** is
used for decisions, interpretations, and arguments; **claim strength** is
mid-range ("suggests" / "indicates").

**`references/principles.md`, on demand.** It holds the verified
reader-cognition sources behind the Stage 3 diagnosis items (Gopen & Swan
1990; Williams & Bizup; Clark & Haviland 1977; Halliday & Hasan 1976;
Mensh & Kording 2017, et al.) — the one line of principle the manual's
corpus does not contain. Its content is already embedded in the ② bullets,
so read the file itself only when the user asks for the theory or sources
behind an information-flow judgment.

## Stage 3 — 진단 (Diagnose) — output blocks ①–③

### ① 의도 요약

State the paragraph's core claim and its role (2-3 lines, Korean). This is
your reading, offered for orientation — do not stop to ask for
confirmation; the user will correct you if it is off. C안 in Stage 4
rewrites from this intent, so get it right.

### ② 논리 흐름·명확성 논의

Free prose in Korean — this is the heart of the review, so discuss openly
rather than filling a form. Cover whatever genuinely matters for THIS
paragraph, typically:

- claim-evidence linkage: does each assertion have visible support?
  Results-style paragraphs read best as question → data/logic → answer.
- logical gaps or jumps between sentences; unstated premises
- information flow (old-before-new): each sentence should open with what
  the reader already knows and land its new point at the end, where
  emphasis naturally falls — readers must otherwise hold the new
  information in memory until they find its anchor. Check the topic
  string: the openings of the sentences should stay within one small set
  of related ideas; random topic shifts read as drift.
- ambiguous referents ("this", "these results", "such effects"): a
  referent with two plausible antecedents is automatically 高 — readers
  have no repair strategy for it.
- hedging calibration, in BOTH directions: the academic norm is
  mid-strength ("suggests", "indicates"). Flag bare "proves/demonstrates"
  AND hedge-stacking ("seems to suggest that ... could") — and remember
  that omitting a hedge is itself the most common intensifier.
- sentence-level clarity: are the main actors the grammatical subjects,
  and the key actions the verbs? Nominalizations in subject position are
  the telltale sign of turgid prose.
- paragraph shape (context–content–conclusion): first sentence sets the
  topic, last sentence states what the reader should carry away; one
  point per paragraph, each sub-topic handled in one place only.
- argument soundness — the principles above govern how information is
  *arranged*; this one asks whether the reasoning *holds*. A paragraph can
  be perfectly ordered and still argue badly. Watch for: correlation
  stated as cause; a conclusion broader than the evidence (single site,
  single run → general claim); circular support (the claim restated as its
  own reason); false dichotomy; and self-contradiction between sentences.
  Name the specific move, not just "logic is weak".
- internal consistency — within this one paragraph, is the tense stable,
  the person stable ("we" vs "the authors"), and each concept named by one
  term throughout? Switching terms for variety reads as switching
  referents.
- redundancy — the diagnosis so far only asks what to *fix*. Also ask what
  to *cut*: take each sentence out in turn, and if the paragraph's claim
  and evidence survive intact, that sentence is redundant (中). Say which
  sentences failed this test.

Quote the actual problem phrases when you discuss them. When a finding
maps to a manual principle, cite its ID (예: `paragraph-logic-21`) — it
makes the diagnosis traceable to the standard, not just to your judgment.
Close ② with one line naming the guideline sources you applied (예:
"적용 지침: 문장 스타일 공통 · 인용 규범 · Results 블록 · manual
00_universal + 04_results") — a skipped source should be visible, not
silent.

### ③ 문장별 진단 표

Number the sentences, then table ONLY the sentences with findings, in
sentence order:

| # | 문제 | 심각도 |
|---|---|---|
| 2 | 주어가 불명확 — "It"이 가리키는 대상이 두 가지로 읽힘 | 中 |

Severity scale: 高 / 中 / 低, assigned by **how global the damage is** —
a defect that misleads the reader about the argument outranks one that
merely slows them down:

- **高** — the reader takes away something wrong or cannot recover the
  meaning: unsound reasoning, a claim beyond the evidence, an ambiguous
  referent with two plausible antecedents, a missing required element of
  the section, broken information flow across the paragraph.
- **中** — the reader gets there, but pays: clumsy ordering, redundant
  sentences, inconsistent terms or tense, run-ons, table/text duplication.
- **低** — local polish: filler intensifiers, clichés, contractions,
  wordy constructions.

Fix in that order too. Rewriting a sentence that is about to be cut, or
polishing wording inside a paragraph whose logic must be rebuilt, is
wasted work.

Close the table with one line naming the clean sentences: "문장 1, 4 —
수정 불필요." If no sentence is clean, write "수정 불필요 문장: 없음."

## Stage 4 — 대안 (Alternatives) — output blocks ④–⑤

### ④ 리라이팅 3안

Three complete, self-contained paragraphs — each usable as-is, none a
sketch. They differ in **how much of the original survives**, so they must
not drift toward each other: if B reads as A with two commas moved, the
author has been handed one option three times. Label each with a 1-2 line
change summary (Korean), and follow each English paragraph with its
**국문 번역** — a faithful translation of that alternative, so the author
can check the meaning without re-parsing the English. Translate what the
alternative actually says (including any `[근거 필요]` markers), not what
the original said.

- **A안 — 최소수정**: keep the sentence order; polish wording, referents,
  and hedging only. Sentences you named clean in ③ stay untouched —
  "minimal" means minimal, and rewriting what already works is how a
  review loses the author's trust.
- **B안 — 재배치**: reorder, merge, or split sentences; rebuild transitions
  so the logic reads in sequence. The sentences remain recognizably the
  author's.
- **C안 — 재구성**: write the paragraph **the loaded principles would
  produce**. Re-derive the argument structure — what is claimed, what
  supports it, in what order — from the intent in ①, then draft as if the
  original's sentences did not exist, applying the Stage 2 standards in
  full: topic sentence first, old-before-new flow, one idea per sentence,
  concision (every word earning its place), active voice by default,
  plain words, mid-strength hedging, C-C-C shape. The author's facts and
  intent are the anchor; the original's phrasing is not. This is the
  principle-exemplar version, not B with synonyms swapped.

**Preservation guardrail (applies to all three):** carry over every data
point (values, units, uncertainties), every citation, and every
figure/table number verbatim. Claims, however, may be recalibrated —
hedging strength, scope, causal language — whenever ②'s diagnosis flags
them as overclaimed, overgeneralized, or unsupported by the evidence in
the paragraph; logic and clarity outrank literal preservation.
Recalibrating a claim changes what the author asserts, so flag it for
confirmation rather than presenting it as settled: say which claim moved,
in which direction, and on what basis, in that alternative's change
summary. The author decides whether the weaker or stronger reading is the
one they meant.

**Vagueness is a fact too — translate it, don't resolve it.** When the
draft is Korean (or simply vague), render ambiguous relational wording at
its own level of vagueness: "함께 수행하였다" → "in parallel" or "was also
performed", never "on the same samples" or "on a subset" — those are
factual specifics the draft does not state, and inventing them is
fabrication exactly like inventing an instrument model. If the vagueness
itself is a defect worth fixing, flag it in ② and mark the missing
specific with `[근거 필요]`; do not quietly pick one reading.

**Adding sentences is allowed.** Cutting is not the only repair. Where ②
found a logical gap, an unsupported claim, or a missing required element
of the section, an alternative may add the sentence that closes it. Two
limits, both absolute: never invent a data point, a citation, a
figure/table number, or a numeric magnitude; and where the added sentence
needs evidence the paragraph does not contain, write it with a
**`[근거 필요]`** marker standing in for that evidence rather than
supplying it yourself. Name every addition in the change summary.

**The original may be the best version — but test it, don't defer to
it.** The three alternatives are your own output, and there is no reason
to assume they beat what the author wrote — a model asked for rewrites
produces them whether or not they improve anything. When ② and ③ turn up
nothing above 低 AND the original already satisfies the Stage 2
principles, say so plainly and offer the alternatives as options rather
than corrections. That is a verdict about the original's principle
conformity, not a license to prefer it because it is the original.

Note also what this skill does **not** check: whether the citations and
numbers are real. It carries them over verbatim, so if the draft was
itself AI-generated, a fabricated citation survives into all three
alternatives untouched. Verifying sources against the originals stays
with the author.

**Priority when principles collide:** the paragraph's information flow
(old-before-new cohesion) outranks the polish of any individual sentence —
"a passage's overall cohesion trumps the clarity of individual sentences"
(Williams & Bizup).

### ⑤ 권고·다음 행동

Open with one judgment line: which of A/B/C you recommend for THIS
paragraph and why in a clause — or "원문 유지" if the original wins. The
judgment comes here, after all three are built at full effort, not before.

**Judge by principle conformity, not by proximity to the original.** The
question is which version best satisfies the Stage 2 standards while
preserving the author's facts and intent — closeness to the original
draft is not a merit in itself, and recommending A or B out of
deference to the author's phrasing defeats the review. Recommend the
conservative rung only when it genuinely scores as well against the
principles; when C reads better as academic prose, say so and recommend
C. (The over-correction brakes in Stage 2 still apply — they bar
*refuted* rules, not principled restructuring.)

Then one closing line of options: *"A/B/C안 채택" · "원문 유지" · "특정 안
수정 요청 (예: B안에서 마지막 문장만)" · "다음 단락"*

Add one more line naming the recurring defect type in this paragraph
(예: "이번 단락의 반복 결함: 모호한 지시어 3건"). Over several paragraphs
these lines accumulate into the author's own checklist, which is worth
more than any single review.

## Completion criterion

The response is complete only when every sentence is either in the
diagnosis table or named in the 수정 불필요 line, AND all three
alternatives are full paragraphs each followed by its 국문 번역, AND ②
names the guideline blocks actually applied, AND ⑤ opens with a
recommendation.

## Follow-up turns

- **채택** ("A안으로") → output that version alone — the English
  paragraph, clean and copy-ready, with its 국문 번역 below it.
- **원문 유지** → confirm in one line; do not re-argue for your rewrites
  or produce a fourth alternative.
- **부분 수정** ("B안에서 두 번째 문장만 바꿔줘") → revise that alternative
  only and re-present it (with updated 국문 번역); keep the other two
  untouched. If the revision changes the ⑤ recommendation, restate it.
- **한국어 원고 요청** (a paragraph that should *be* Korean manuscript
  prose, not a translation) → decline in one line and point to
  `meta-rewriting-korean`. The 국문 번역 in ④ is a comprehension aid;
  Korean prose meant for a manuscript needs a Korean register standard
  this skill does not carry.
- **새 단락** → run the four stages again from Stage 1.
