# Meta-Writing-Insight — Interview, Choose, Draft

A derivative of `meta-writing`. It keeps that skill's procedure — My Data vs Knowledge
distinction, 5-Loop exploration, revision, citation verification — and adds two things
in front of it: an interview that extracts what only the author knows, and a choice of
argument frame made by the author.

## Why this skill exists

A model fills every gap in its input with its prior: "what a section like this usually
says". Revising the draft with more model judgement does not fix this, because the judge
shares the same prior. So this skill puts the author, not a loop, where drafts regress
to the mean:

1. **Originality is an input, not an output.** The draft can only carry the insight the
   author supplied. Phase 1 exists to get it out of the author.
2. **The model never picks the argument.** It offers frames; the author chooses. A
   model's recommendation pulls toward the typical frame.
3. **Keep it simple.** One interview, one choice, one draft, one verification. No
   refinement loop, no distance metrics, no judge panel.

The author takes part three times: the interview (Phase 1), the frame (Phase 3), and the
final wording (Phase 5).

**Two starting points.** From data and sources alone (**new mode**), or from an existing
draft of the section (**draft mode**). Draft mode changes Phases 1, 3, and 4 only; each
phase says how.

**Scope.** English sections only in this version. For a section written in Korean, use
`meta-writing-korean` (new) or `meta-rewriting-korean` (existing text).

## Phase 0 — Setup

Load `writing.local.md` exactly as `meta-writing` §Project Settings Load does, and build
the `meta-writing` `<task_spec>`. Use `./insight/` as the working folder.

**Draft mode.** If the user supplies an existing draft of the section, copy it to
`insight/draft_input.md` and ask once: "Did you write this draft yourself, or was it
generated (for example by meta-writing)?" Record the answer in `state.md` as
`draft_origin: author` or `draft_origin: model`. The answer decides how much of the
draft Phase 4 keeps.

**Resuming.** If `insight/state.md` exists, read it and continue from the phase it
records instead of starting over. Update `state.md` at the end of every phase: current
phase, chosen frame, open questions.

**No author present.** If no one can answer the interview, do not invent a brief. Run
plain `meta-writing` and state at the top of the output that the interview was skipped.
If the author leaves at a later checkpoint (Phase 3 or 5), stop there, save `state.md`,
and wait.

## Phase 1 — Interview: the Insight Brief

Interview the author until the section's argument is theirs rather than the model's.

**Facts first, from the files.** When Phase 1 begins, dispatch a subagent to run
`meta-writing` Loops 1–3 (source scan, Knowledge reading, My Data analysis). Questions
cite what it finds. Never ask the author for anything the files can answer. Loop 4 (gap
check and web search) waits until the brief is confirmed, since it depends on the core
message.

**How to ask.** Plain text, in the user's language. At most five numbered questions per
round, then wait for the answers. Each question states the data fact that prompted it.
**Do not offer a recommended or model answer** — the author answers in their own words.

```
❓ **Q1** - **<title>**
<the fact from the files, e.g. "In Fig. 2, As at site B is three times the other sites.">
<the question, e.g. "Did you expect this? If not, what did you expect?">
```

A question that depends on another open question goes to the next round. Stop asking
when the questions below are answered or pruned.

| Ask about | What it extracts |
|---|---|
| **Surprise** | What in this data did the author not expect? |
| **Tension** | Which specific prior finding (author, year) does this result strain? |
| **Rival explanation** | What else could produce this pattern, and why does the author reject it? |
| **Field knowledge** | What does the author know from the field, the lab, or the samples that is in no file? |
| **Boundary** | What will the author explicitly refuse to claim? |
| **Stake** | If a reader remembers one sentence, which one? (This becomes `Core message`.) |
| **Leading word** | A compact term or metaphor the whole section can hang on |

Prune questions the section does not need. When an idea keeps recurring, ask the author
to name it — that name is the leading word.

**Draft mode: start from the draft.** Before the questions above, list the draft's
claim sentences, numbered and quoted, in one message. Ask the author to mark each:

- **keep** — becomes a `[MUST-KEEP]` fragment
- **wrong** or **too generic** — ask why, in the next round. The answer is usually where
  the insight is.
- **cut** — record it; the claim does not go into the new version

Then ask only the questions from the table that the draft does not already answer.

**"I don't know."** Close that question and record it as `[OPEN]`. Do not fill it in.

### Recording the brief

Write the answers to `insight/insight_brief.md` as numbered fragments (F1, F2, …), in the
author's words. Re-read the file before every write, since the author may edit it. Tag
each fragment:

- `[MUST-KEEP]` — a claim the section must contain, at this strength
- `[BOUNDARY]` — something the section must not claim
- `[AUTHOR]` — an interpretation or field observation the author supplies with no source.
  It may appear in the text only as the author's own statement, never with a citation.
  `meta-writing` §Interpretation Boundary reserves interpretation for the author; here the
  author is the one supplying it.
- `[LEADING-WORD]` — the coined term
- `[OPEN]` — a question the author could not answer

**Done** when the author confirms the brief. Do not proceed on an unconfirmed brief.

---

## Phase 2 — Knowledge exploration

Complete `meta-writing` Phase 2 (Loops 1–4 and the Gap Check), reusing what already ran
in Phase 1. Two additions:

- For each `[MUST-KEEP]` claim that touches the literature, find the specific source it
  agrees or disagrees with. The tension the author named must be anchored to a real
  citation, not to "previous studies".
- For each `[AUTHOR]` fragment, search the collected sources. If a source already states
  it, tell the author and cite the source instead. If a source contradicts it, tell the
  author before drafting.

---

## Phase 3 — Choose the frame

**Draft mode.** One of the frames is the draft's current structure, labelled **Current**,
written as a skeleton table like the others. Add two alternatives. If the author picks
Current, the structure stays and Phase 4 changes sentences only.

Write three frames (four if the brief clearly supports it) as skeletons in the
`writing_template.md` §5-0 table format — no prose yet. Every frame carries every
`[MUST-KEEP]` claim and crosses no `[BOUNDARY]`. Frames differ in the move that opens and
organises the section, and no two share the same paragraph order:

| Frame | Opens with |
|---|---|
| Anomaly-first | The surprise, then what it overturns |
| Rival-first | The competing explanation, then the evidence that excludes it |
| Mechanism-first | The proposed process, then the observations it predicts |
| Boundary-first | What the data cannot show, then what it can |
| Field-first | An `[AUTHOR]` field observation, then the data that corroborates it |
| Leading-word-first | The coined term, defined by this study's evidence |
| Consequence-first | The implication, then the chain of evidence back to the data |

Present each frame with:

- the opening two sentences, written out
- the skeleton table
- one line on what the frame bets on ("this frame bets that the reader cares more about
  the rival explanation than about the mechanism")

The author picks one or combines them. **Do not rank the frames and do not recommend
one.** Save all frames and the choice to `insight/frames.md`.

---

## Phase 4 — Draft

Write prose for the chosen skeleton under every `meta-writing` Phase 3 rule (Core Rules,
Paragraph Writing Rules, Source Language Discipline), reading `section_guides.md` and the
manual for the section. Then run `meta-writing` Phase 3.5 once. While drafting:

- **Specific details come from the files only.** Sample IDs, site names, analytical
  conditions, and values come from My Data or the brief. A detail found in neither is
  fabrication, however human it sounds.
- **Define before use.** The leading word is defined where it first appears, and not
  used before that.
- **Mark provenance in the working copy.** After each sentence built on a brief fragment,
  add its number, e.g. `[F4]`. Only numbers that exist in the brief may be used. Save as
  `insight/draft_working.md`. The marks are removed from the final text.

**Draft mode: revise, do not start over.** Work from `insight/draft_input.md`.

- `draft_origin: author` — the draft carries the author's own sentences and voice.
  Keep each sentence unless the chosen frame, a `[MUST-KEEP]`/`[BOUNDARY]` fragment, a
  **cut** mark, or a factual error requires a change. Never replace an author sentence
  just to make it read better.
- `draft_origin: model` — the draft is the average the author reacted against. Rewrite
  freely; keep only its verified citations and numbers.

Either way, list every changed sentence (before → after, and the reason) in
`insight/changes.md`. Treat the draft's own citations and numbers as unchecked: they go
through Phase 2 and Phase 6 like everything else.

### Brief check

After Phase 3.5, check the working copy against the brief once, and save the result to
`insight/brief_check.md`:

| Check | Pass condition |
|---|---|
| Every `[MUST-KEEP]` | Quote the sentence that carries it. Same claim, no weaker, no broader or narrower in scope |
| Every `[BOUNDARY]` | No sentence crosses it |
| Every `[AUTHOR]` sentence | Traces to a fragment number, and says no more than the fragment |
| Every other claim sentence | No stronger than its source says (a source's "may" stays "may") |
| Every `[OPEN]` | Appears as `[interpretation needed — no supporting source]`, not filled in |

Fix any failure in the draft, then re-run the check on the changed sentences.

---

## Phase 5 — Author's wording

Show the author the draft and ask which paragraphs they want to rewrite themselves.
Voice is the author's; the model does not optimise it.

If the author gives one or two paragraphs of their own earlier writing and asks for it,
offer a variant of at most two paragraphs in that style. Before showing any variant, run
the brief check and the number check (Phase 6) on it.

---

## Phase 6 — Verification

Run `meta-writing` Phase 4 in full: Steps 1–5 and the Verification Checklist. Step 3
(claim-source fidelity) is not optional. Add two checks:

- **Numbers.** Every number in the text matches a value in My Data or the brief, with
  the same unit. A derived value (a ratio, a percent change) lists its calculation in F).
  Values read from a figure image keep `~` as `meta-writing` §My Data Handling requires.
- **Author statements.** Using the working copy's marks, every `[AUTHOR]` sentence reads
  as the author's own statement ("we observed", "this study") and carries no citation.

Then remove the provenance marks and write `insight/final.md`.

| Block | Content |
|---|---|
| A–F | As in `meta-writing`. In draft mode, A) links to `insight/changes.md` |
| G) AI Assistance Log | Check **전환적** (transformative) as the intervention level, because the skill proposed the argument frames. List what the author supplied (the brief, the frame choice, the rewritten paragraphs) separately from what the model produced. |
| **H) Brief Preservation** | Each `[MUST-KEEP]` with the sentence that carries it; each `[BOUNDARY]`; the `[OPEN]` items still awaiting the author; the frames not chosen, kept for revision rounds |

Label C) Main Text as a draft.

## Constraints

- **Human-like is not detector evasion.** Never use or optimise against an AI detector,
  and never strip provenance marks, hidden characters, C2PA data, or document metadata.
  G) must disclose AI assistance.
- **Originality never comes from unsupported claims.** A sentence that is new because it
  asserts something no source or brief fragment supports is removed or marked
  `[interpretation needed — no supporting source]`.
- **Everything in `meta-writing` §Constraints applies**: citation strictness, secondary
  citations, interpretation boundary, My Data handling.
- **Files, not memory.** Everything lives in `insight/`, so a later session can resume
  and the author can audit each step.
