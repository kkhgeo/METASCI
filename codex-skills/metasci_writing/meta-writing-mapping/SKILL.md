# meta-writing-mapping — 계층형 글 구성 논의

원고의 **섹션·소절·단락 배치와 근거 결속을 사용자와 함께 결정**한다. 문장은
쓰지 않는다. 산출물의 기준 원본은 작업 폴더의 `outline.md` 하나다. 전체 원고와
부분 섹션은 별도 문서가 아니라 같은 원고 지도를 서로 다른 배율로 본다.

## 하는 일 / 안 하는 일

| 한다 | 안 한다 |
|---|---|
| 전체·섹션·소절·단락군의 구조를 설계·진단 | 본문 문장 작성 → `meta-writing` |
| 단락 기능·논지·논리 간선·근거·Ledger를 배정 | 문장 교정 → `meta-proofreading` |
| 구조 결함을 우선순위가 있는 결정으로 변환 | 단락 재작성 → `meta-rewriting` |
| 사용자와 중요한 갈림길을 하나씩 확정 | 문체 손질 → `meta-styling` |
| 필요할 때 `outline-dashboard.html`을 자동 파생 | HTML을 원본으로 직접 편집 |

## 핵심 원칙

1. **범위를 묻지 않고 판별한다.** 전체인지 부분인지 사용자 요청, 지정 파일,
   `outline.md`의 현재 위치로 판단한다. 불명확해도 가장 좁은 안전 범위로 시작하고
   첫 응답에 해석한 범위를 한 줄로 밝힌다.
2. **부분 작업도 전체 맥락을 잃지 않는다.** 전체 `outline.md`가 있으면 Core
   message, 상위 섹션 기능, 대상 범위의 앞뒤 경계 노드만 읽는다. 전체 표를 다시
   펼치지 않는다.
3. **전체 지도가 없으면 국소 지도를 거부하지 않는다.** `provisional` 상태로
   만들고 확인할 수 없는 상위 연결을 명시한다. 나중에 전체 지도에 병합할 때
   충돌한 결정은 `reopened`로 바꾼다.
4. **분석 결과를 승인하라고 넘기지 않는다.** 모든 질문에는 추천안, 추천 근거,
   대안의 비용, 영향 범위, 짧은 응답 선택지를 붙인다. 사용자는 `채택 / 대안 /
   부분 수정 / 보류`로 답할 수 있어야 한다.
5. **예외 중심 승인.** 근거가 명확하고 영향이 작은 결정은 `provisional`로
   진행한다. Core message, 섹션 경계, 결과–고찰 분리, 근거 부족, 범위 변경처럼
   영향이 크거나 불확실한 결정에서만 멈춘다.
6. **한 번에 결정 하나.** 지적은 최대 3개까지 요약할 수 있으나 질문은 현재
   가장 높은 우선순위 결정 하나만 한다. 다음 결정은 앞 결정이 `decided` 또는
   `deferred`가 된 뒤 꺼낸다.
7. **안정적 ID와 생명주기.** 단락·근거·Ledger·결정 ID는 재번호화하지 않는다.
   해결된 항목은 삭제하지 않고 `resolved`로 보관하되 활성 대기열에서는 숨긴다.
8. **부분 변경의 파급을 조용히 반영하지 않는다.** 현재 범위 안은 수정할 수
   있지만 범위 밖에서 영향을 받은 결정은 `reopened`로 등록한다.
9. **근거 없는 단락은 설계 결함이다.** 단락당 웹 검색은 2회까지다. 못 찾으면
   `⚠ 근거없음`으로 두고 삭제·범위 축소·사용자 자료 요청 중 하나를 추천한다.
10. **대화가 주, 뷰는 보조다.** 그래프·행렬·검증표는 별도 HTML에 두고 대화에는
    현재 결정과 그 근거만 가져온다. 검사 보고서를 그대로 쏟아붓지 않는다.
11. **저장은 물어본다.** `outline.md`를 처음 만들거나 구조적 결정을 반영하기
    전에 확인한다. 단, 사용자가 명시적으로 파일 수정을 지시한 경우에는 바로
    반영하고 변경 내용을 보고한다.
12. **사용자 판단이 규칙을 이긴다.** 근거를 대고 한 번 반대하되 재확인하면
    따르고 결정 이력에 이유를 남긴다.

## 범위 계층

범위는 다음 네 수준 가운데 자동 판별한다.

| 수준 | 예 | 검토 단위 |
|---|---|---|
| manuscript | 원고 전체 | Core message, 섹션 체인, Methods↔Results, 질문↔답 |
| section | `Discussion` | 섹션 기능, 내부 단락군, 앞뒤 섹션 연결 |
| subsection | `Results 3.4` | 소절 내부 사슬, 근거 착지, 경계 간선 |
| paragraph-group | `3.4 P1–P3` | 대상 단락군 + 앞뒤 경계 노드 1개씩 |

현재 범위보다 상위의 미확정 결정이 작업을 막으면 그 결정만 함께 올린다. 관련 없는
다른 섹션의 미해결 항목은 보여주지 않는다.

## 시작 절차

1. 작업 폴더에서 `outline.md`, 초고(.docx/.md/.tex), `figures/`, `tables/`,
   `knowledge/`, `pdf/`를 확인한다.
2. `outline.md`가 있으면 `references/outline-format.md`에 따라 메타데이터,
   대상 범위 노드, 경계 노드, 활성 결정만 읽는다. 근거 노트에 이미 기록된 자료는
   다시 읽지 않는다.
3. `outline.md`가 없으면 자료를 정독해 가장 좁은 유효 범위의 지도를 만든다.
   전체 정보가 부족하면 `provisional`로 표시한다.
4. 구조를 지적하기 전에 `references/rule-routing.md`를 읽는다.
5. 사용자와 결정을 시작하기 전에 `references/decision-protocol.md`를 읽는다.
6. 첫 응답은 다음 순서다.
   - 해석한 범위 한 줄
   - 본 자료와 현재 구조의 중심 한 단락
   - 가장 중요한 구조 문제 최대 3개
   - 추천이 포함된 결정 카드 하나

## 결정 카드

질문은 반드시 다음 형식을 따른다.

```text
[D-### · 우선순위 · 범위] 결정 제목

추천: 모델이 고른 안
근거: 왜 이 안이 현재 자료와 Core message에 가장 잘 맞는지
대안의 비용: 다른 안을 택하면 무엇을 다시 배치하거나 포기해야 하는지
영향: 영향을 받는 섹션·단락·근거·후속 결정

판정: 추천 채택 / 대안 채택 / 부분 수정 / 보류
```

개방형 질문("어떻게 할까요?")만 던지지 않는다. 사용자에게 판단 근거가 없으면
모델이 먼저 분석을 더 하고 추천을 만든다.

## 결정 생명주기

`references/outline-format.md`의 결정 대장은 다음 상태를 쓴다.

```text
detected → surfaced → decided → resolved
                    ↘ deferred
어느 상태에서든 → superseded
resolved/deferred → reopened
```

- `detected`: 발견했지만 아직 사용자에게 말하지 않음
- `surfaced`: 현재 대화에 올림
- `decided`: 사용자가 방향을 정함
- `resolved`: 결정이 outline에 반영되고 구조 검증을 통과함
- `deferred`: 의도적으로 뒤로 미룸
- `superseded`: 다른 결정으로 대체됨
- `reopened`: 후속 변경으로 다시 검토해야 함

`resolved`와 `superseded`는 기록에 남기되 활성 대기열에서 제외한다. 결번은 정상이다.
ID를 당기거나 재사용하지 않는다.

## 부분 mapping 절차

1. **범위 선언** — 예: `Results 3.4 / P1–P3`.
2. **상위 맥락 투영** — Core message, 상위 섹션 역할, 들어오는 간선, 나가는
   간선만 표시한다.
3. **내부 사슬 점검** — 기능, 한 줄 논지, 논리관계, 근거·Ledger 착지를 본다.
4. **범위별 결정 대기열** — 상위 블로커, 현재 범위 결정, 파급 결정만 추린다.
5. **현재 범위 수정** — 합의한 변경만 반영한다.
6. **영향 전파** — 범위 밖 영향은 자동 수정하지 않고 관련 결정을 `reopened`로
   바꾼다.
7. **상위로 복귀** — 부분 작업을 마치면 전체 지도에서 달라진 연결을 한 문단으로
   요약한다.

전체 `outline.md`가 없으면 2단계에서 가정을 명시하고 국소 지도를
`provisional`로 둔다. 나중에 전체 지도와 병합하기 전에는 전체 정합성을 통과했다고
말하지 않는다.

## 구조 뷰와 자동 검증

`outline.md`가 길거나 다대다 관계가 많으면 다음을 실행할 수 있다.

```bash
python scripts/outline_map.py lint outline.md
python scripts/outline_map.py queue outline.md --scope RESULTS.3.4
python scripts/outline_map.py dashboard outline.md --out outline-dashboard.html
```

대시보드는 원본이 아니라 자동 파생물이다.

- **결정 대기열** — 블로커·고영향·근거 결손·논리 단절·기계적 항목 순
- **논리 그래프** — 단락 노드, 논리 간선, 선택한 사용자 정의 축
- **근거 매트릭스** — Figure/Table/Ledger와 단락의 다대다 착지
- **검증 결과** — 고아 노드, 미배정 근거, first-report 중복, 깨진 참조
- **해소 기록** — resolved·superseded 결정

HTML 전체를 대화에 붙이지 않는다. 뷰가 찾아낸 상위 1–3개만 규칙 이름과 함께
대화로 가져온다. 기존 6열·세로 형식 outline은 읽을 수 있으나 자동 파생 정확도가
낮으면 `legacy parse` 경고를 낸다. 사용자의 승인 없이 새 형식으로 덮어쓰지 않는다.

## 완료 기준

mapping은 다음을 만족할 때 완료된다.

- 현재 범위의 핵심 주장과 기능이 `decided` 이상
- 각 단락의 근거 또는 `⚠ 근거없음` 처리 방향이 명시됨
- 내부 논리 간선과 경계 간선이 기록됨
- 활성 blocker가 없음
- 부분 변경으로 영향받은 범위 밖 결정이 `reopened`로 기록됨
- 사용자에게 모의 독해를 제시하고 빠진 핵심·과도한 강조·질문 불일치를 확인함
- 마지막으로 반대 심사자 관점의 구조 위험을 최대 3개 검토함

## 참고 파일

- `references/outline-format.md` — 계층형 ID, 구조 노드, 인벤토리, 결정 대장,
  구형 outline 호환 규칙
- `references/decision-protocol.md` — 추천 중심 승인, 우선순위, 상태 전환,
  영향 전파
- `references/scope-projection.md` — 전체·섹션·소절·단락군 투영 규칙
- `references/rule-routing.md` — 구조 판단에 적용할 규칙과 발화 방식
- `references/section-checklists.md` — 섹션별 필수 구조
- `references/structural-integrity.md` — 전체 원고의 질문·방법·결과·고찰 정합
