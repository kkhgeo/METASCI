# Meta Writing Skill

## Overview

Combines original research data (My Data) with prior literature knowledge (Knowledge Sources)
to write academic paper sections.

**Two types of information are clearly distinguished:**

| Category | My Data (Original Research) | Knowledge Sources (Prior Literature) |
|----------|---------------------------|--------------------------------------|
| Identity | Data produced by the researcher | Knowledge drawn from prior studies |
| Examples | Figure, Table, CSV | Knowledge MD, PDF, Web |
| Role in text | Subject of description/interpretation | Basis for comparison/evidence |
| Results | "This study showed ~ (Figure 1)" | "Similar to (Chen et al., 2024)" |
| Discussion | "The observed pattern suggests ~" | "Explained by Chen (2024)'s model" |

**Knowledge Sources Priority:**
1. Knowledge folder (markdown) — Already structured knowledge, always first priority
2. PDF folder — Supplements papers not covered by Knowledge
3. Web search — Latest information or gap filling

## Knowledge Exploration and Analysis (Phase 2)

Explore and analyze sources using the 5-Loop process.

The Loop Summary below is the step sequence — follow it directly. Loops 1-4 of
`references/writing_template.md` add what the summary leaves out: the Claim+Citation
extraction format, the My Data analysis procedure, the gap-report template, web-search
rules, and per-source handling for Knowledge markdown, PDFs, and web results. Open it
when a step needs a format or a rule the summary does not supply.

### Loop Summary

```
Loop 1: Source Scan and Planning
  - Load writing.local.md (if available)
  - Check My Data folder (list figures/tables/data)
  - Check Knowledge folder (index.md, select relevant files)
  - Check PDF folder
  - Establish exploration plan

Loop 2: Knowledge Reading
  - Read selected Knowledge markdown files (up to 5)
  - Extract Claim + Citation pairs
  - Intermediate Result A

Loop 3: My Data Analysis + Additional Sources
  - Analyze My Data figures/tables (extract patterns, values)
  - Generate comparison pairs between My Data and Knowledge
  - Read additional Knowledge/PDF files
  - Intermediate Result B

Loop 4: Gap Check + Web Search
  - Verify citation count, topic coverage, recent research, comparison data
  - If insufficient, supplement with Web search (if allowed)
  - Intermediate Result C + Gap Report
```

Loop 1 counts the sources. At 3 or more Knowledge files, 2 or more PDFs, or figures and
tables both present, read `references/parallel-processing.md` and run Loops 2-4 as
subagents — it carries the thresholds and the subagent prompts. One or two sources run
sequentially.

### Gap Check Criteria

| Gap Type | Judgment Criteria | Response |
|----------|------------------|----------|
| Insufficient citations | Below minimum citation count | Additional PDF/Web search |
| Insufficient comparison data | No prior studies matching My Data patterns | Web search |
| Insufficient recent research | No studies after 2023 | Web search |
| Insufficient interpretation basis | No theories/mechanisms to cite in Discussion | PDF/Web search |

## Writing (Phase 3)

Read three things before drafting each section, in this order:

| Read | For |
|---|---|
| `references/writing_template.md` §Loop 5 | The drafting procedure — settle the skeleton, then write prose |
| `references/section_guides.md` §<section> | **How** to write it — structure, transitions, worked phrasing, tense, voice, citation density, expressions to avoid |
| `claude_writing_manual/00_universal.md` + the matching section file | **What must be in it** — required elements, anti-patterns, and the source behind each |

The manual sits at `references/claude_writing_manual/`, inside this skill. Read those two
files, not the folder. It holds 327 principles indexed by section, each carrying a verbatim source
quote, its supporting sources, and its verification status; 131 of them appear in no other
reference here. Open `INDEX.md` when unsure which file covers a topic. When the user asks
why a rule holds, or needs a source to give a supervisor or reviewer, quote the principle's
own citation.

Three questions the corpus leaves open — **abstract length, title length, abstract voice** —
are settled by the target journal rather than by evidence. On reaching one, read
`claude_writing_manual/DECISIONS.md`, put both positions to the user with their sources,
and ask which applies. Record the answer in the draft.

Two further questions are already settled; offer them as decided, not as options. First
person carries decisions, interpretations, and arguments. Claim strength sits mid-range
("suggests", "indicates"). `claude_writing_manual/DIAGNOSTIC-MAP.md` records the reasoning,
and is what to consult when the manual and another reference here appear to disagree.

### Core Rules

**My Data vs Knowledge Distinction Principle:**
- My Data is described directly without citations. Reference as "(Figure 1)", "(Table 2)".
- Knowledge Sources must always be cited in (Author, Year) format.
- When mixing My Data and Knowledge in a single sentence, clearly indicate which is original research and which is prior literature.

**Paragraph Writing Rules:**
1. Topic sentence: Begin with the central claim
2. Evidence: Cite Knowledge Sources at the density set for this section in
   `section_guides.md` §인용 밀도
3. Transitions: Connect to the previous paragraph's last idea
4. Concluding sentence: State implications or connect to the next paragraph
5. Source diversity: Mix different source types when possible
6. One idea per sentence: Split sentences that carry two independent claims
7. Density: Every sentence must earn its place. Cut wording that adds no information
8. Reader level: Unpack terms an `adjacent-field` reader would not know, unless
   `Target reader: specialist` was set

**Source Language Discipline** — guards against plagiarism and against distorting what a
source said:
- Restate everything you borrow in your own wording. The Claim strings collected in Loop 2
  are *notes*, not draft text. A sentence from a Knowledge markdown, PDF, or web page
  reaches the manuscript only as a marked quotation.
- Where exact wording genuinely carries the point, quote it — quotation marks, the source,
  and kept short.
- Restate at the original's scope, strength, and emphasis. A sample-level finding stays
  sample-level; a hedged finding stays hedged. This is the one place that rule lives —
  it governs Phase 3 drafting and Phase 4 Step 3 alike.
- Choose each reporting verb to match what the cited author actually did, and a fresh verb
  for each consecutive citation. The verb-to-action table is in `section_guides.md`
  §Reporting verb 선택.

**Bilingual Output:**
- English first, followed by Korean translation
- Maintain consistency of academic terminology
- Keep (Author, Year) citations in English even in Korean text

## Revision (Phase 3.5)

The draft from Phase 3 is a first pass, not the output. Run one revision pass before
verification. **Work global-first, local-last** — fixing commas in a paragraph that is
about to be deleted is wasted effort.

### Global pass (logic and focus)

- [ ] **Core message test** — does every paragraph advance the `Core message`? Name the
      contribution of each paragraph in one clause. A paragraph with no answer gets cut.
- [ ] **Deletion test** — remove each paragraph in turn. If nothing downstream breaks and
      no information is lost, delete it permanently.
- [ ] **Order** — do the paragraphs follow the order set in `writing_template.md` §5-3?
      Do Results and Discussion follow the same sequence as Methods?
- [ ] **Coverage** — is any claim in the section left unsupported, and is any collected
      source left unused for no reason?

### Local pass (language)

- [ ] Sentences carrying two claims are split (Rule 6)
- [ ] Wording that adds no information is cut (Rule 7)
- [ ] Reporting verbs are varied and match the cited author's stance
- [ ] Terms unfamiliar to the `Target reader` are unpacked at first use
- [ ] Tense and terminology are consistent across the whole section, and the English and
      Korean versions still say the same thing

Record what changed in this pass — it feeds A) Approach Checklist.

## Verification (Phase 4)

The five steps below are the sequence — follow them directly.
`references/citation-and-verification.md` supplies what each step needs: in-text citation
forms per source type, APA 7 required fields, the Step 3 fidelity procedure, the
post-verification correction rules, and the report template Step 5 fills in.

### Verification Summary

```
Step 1: Citation-Reference matching (in-text citations <-> References)
Step 2: APA 7 format verification (required fields, formatting)
Step 3: Claim-Source fidelity (does the cited work actually support the claim?)
Step 4: Source-specific verification (Knowledge original cross-check, PDF metadata, Web URL)
Step 5: Generate verification report (PASS / ISSUES FOUND status + issue list)
```

**Step 3 is not optional.** Steps 1-2 only prove that a citation *exists* and is formatted
correctly. They cannot catch misattribution — citing a real paper for a claim it does not
make. For every claim-citation pair, go back to the source text and confirm the source
states it. Mark anything you cannot confirm as `[unverified claim]` and report it.

### Verification Checklist
- [ ] All in-text citations exist in References
- [ ] No orphan references
- [ ] APA 7 format compliance
- [ ] **Each claim is supported by the source cited for it** (not just that the source exists)
- [ ] **Citations inherited from a Knowledge file were traced to their original source**,
      or are flagged as unverified secondary citations
- [ ] My Data references (Figure/Table) match actual files
- [ ] **Every supplied figure/table is referenced somewhere in the text** (reverse check)
- [ ] Values read from figure images are marked approximate unless taken from raw data
- [ ] No fabrication of DOI/URL/year/author
- [ ] No verbatim sentences carried over from sources without quotation marks

## Output Format

The seven blocks below are the deliverable. `references/writing_template.md` §출력 형식 상세
holds the fill-in template for each, including the G) AI Assistance Log disclosure draft.

All output consists of the following 7 sections:

| Section | Content |
|---------|---------|
| A) Approach Checklist | 3-8 step task summary (English + Korean) |
| B) Source Summary | Summary by source type + gap report |
| C) Main Text | English paragraphs + Korean translation |
| D) References | APA 7, single alphabetical list (no source-type grouping/markers) |
| E) Self-Assessment | Quality checklist (self-reported — not quality assurance) |
| F) Verification Report | Reference verification report |
| G) AI Assistance Log | What this skill did and did not do + disclosure draft |

**C) Main Text is a draft, not a finished section.** Label it as such. The author decides
the argument, validates the interpretation, and owns the final wording. Where a sentence
rests on an interpretive judgement the sources do not settle, flag it inline for the author.

**E) and F) are self-reports.** A `✅ PASS` means the checks in this run found no issues,
not that the text is correct. State that alongside the verdict, and cite the file or item
that each check was verified against rather than asserting quality in the abstract.

## Constraints

### Citation Strictness
- Transcribe every DOI, URL, year, and author name from the source in front of you.
  A field you cannot see gets `[missing: field]`
- Web search results carry their source and access date
- **Secondary citations**: Claim-Citation pairs harvested from a Knowledge markdown are
  secondhand — the Knowledge file reports what some other paper said. Before citing that
  original author, confirm the claim against the original work. If the original is not
  available, either cite it as reported (`as reported in [Knowledge source]`) or mark the
  pair `[unverified secondary citation]`. Never present an unchecked secondhand citation
  as if the original had been read.

### Interpretation Boundary
- Map every causal or mechanistic statement to a specific Knowledge claim. An explanation
  with no source behind it belongs to the author, not to the draft.
- Where an interpretation is needed and no source covers it, write
  `[interpretation needed — no supporting source]` and let the author supply it.

### Quality Standards
- Spread the section's support across several sources rather than leaning on one
- Cite selectively — carry the claims the argument rests on. Statements the field treats
  as self-evident stand without a citation

### My Data Handling

Citation form for My Data is set once, in Phase 3 Core Rules. What follows is about
the numbers themselves.

- Carry Figure/Table numbers through exactly as the source files number them
- Report each value as the data file states it
- **Values read off a figure image are approximations.** If raw data (CSV/Excel) exists,
  take numbers from it. Numbers read only from an image are written with `~` and must be
  confirmed by the author before they stand as reported values. If axis labels, units, or
  the legend are unclear, ask — do not estimate.

`section_guides.md` and the manual do not substitute for each other. Writing Methods,
`section_guides.md` gives the sentence patterns and the passive-voice policy; that the
section needs an ethics-approval statement, pre-specified subgroups, primary and secondary
endpoints, and supplier contacts for materials is in the manual alone. The Introduction
anti-patterns — opening with your own lab's development history, opening with praise for
the field, restating the abstract, chaining objectives together — are in the manual alone.
