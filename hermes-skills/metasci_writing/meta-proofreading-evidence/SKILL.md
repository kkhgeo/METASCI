# Meta-Proofreading-Evidence — 표현 용례 점검기 (Phrase Attestation)

## 0. 이 스킬이 하는 단 하나의 일

사용자가 쓴 문장에서 **특징적인 표현·연어(collocation)**를 뽑아,
그 표현이 **실제 출판된 학술논문에 쓰인 적이 있는지**를 검색으로 점검한다.

- **확인되면** → 실제 논문의 원문 예시와 출처(저자·연도·저널·DOI)를 보여준다.
- **확인 안 되면** → "용례 미확인"으로 표시하고, **같은 뜻을 실제 논문이 쓰는
  표현**으로 대안을 제시한다 (반드시 근거 논문 포함).

이 스킬은 문체 교정도, 논리 검토도, 레퍼런스 실재 확인도 하지 않는다.
그건 `meta-proofreading`의 몫이다. 여기서는 **"내 표현이 학계에서
실제로 쓰이는 말인가?"** 만 판정한다.

## 5. Paste 모드 — 붙여넣은 텍스트 점검 (기본 흐름)

### 5a. 표현 추출
`references/phrase_extraction.md` 규칙으로 텍스트에서 **점검 가치가 있는
표현 1~N개**를 뽑는다 (특징적 연어·다어절 전문표현·수사적 정형구 우선,
불용어 조각·고유명사·수치·인용은 제외).

추출 결과를 먼저 사용자에게 보여주고 확인받는다:

```markdown
### 점검 대상 표현 ([N]개)

원문:
**[EN]** `[입력 문장/단락]`
**[KR]** `[번역]`

| # | 표현 | 왜 점검하는가 |
|---|---|---|
| 1 | `aggregate disruption` | 핵심 연어 — 이 조합이 표준인지 |
| 2 | `carbon liberation by frost` | 비표준 의심 표현 |
| ... | ... | ... |

*"이대로 점검" / "표현 추가: [문구]" / "1번 빼줘"*
```

AskUserQuestion으로 승인(옵션: "이대로 점검" / "표현 조정"). 표현이 3개 이하로
명백하면 승인 생략하고 바로 진행해도 된다.

### 5b. 병렬 용례 점검
활성 표현마다 Agent Attest를 **병렬 호출**한다 (한 응답에서 표현 개수만큼
Agent 도구 호출). 각 에이전트에 전달:
- `{phrase}` = 점검할 표현
- `{sentence}` = 그 표현이 들어간 원문 문장 (문맥용)
- `{domain}` = 분야/저널 힌트 (있으면)

각 에이전트는 스스로 검색(OpenAlex 전문검색 → Scholar 따옴표검색 →
Semantic Scholar)하고 `agents/agent_attest.md`의 판정 루브릭을 적용해
구조화된 결과를 반환한다.

표현이 많으면(> 12개) 12개씩 배치로 나눠 순차 실행한다.

### 5c. 결과 렌더링
`§6 출력 형식`에 따라 표현별 판정을 출력한다. 마지막에 요약 테이블.

## 6. 출력 형식

### 표현별 블록

**확인된 표현 (ATTESTED):**
```markdown
#### 1. `aggregate disruption` — ✅ 확인 (전문검색 340건)

실제 논문 용례:
- `...physical **aggregate disruption** releases occluded organic carbon...`
  — Six et al. (2004), *Soil Biology & Biochemistry* (DOI 10.1016/...)

`이 표현은 토양학에서 표준 연어입니다. 그대로 쓰셔도 됩니다.`
```

**드물게 쓰이는 표현 (RARE — 확인되나 빈도 낮음):**
```markdown
#### 2. `frost-driven decarbonation` — 🔶 제한적 (전문검색 3건)

`학술 논문에 쓰이긴 하나 매우 드뭅니다. 아래 더 흔한 변형을 권장합니다.`
- 더 흔한 변형: `frost-induced carbon release` (전문검색 87건)
  — Feng et al. (2020), *Geoderma* (DOI 10.1016/...)
```

**미확인 표현 (NOT FOUND — 대안 제시):**
```markdown
#### 3. `carbon liberation by frost` — ⚠️ 용례 미확인 (전문검색 0건 · 따옴표검색 0건)

`이 표현은 학술 논문에서 확인되지 않습니다. 직역투일 가능성이 높습니다.`

같은 뜻의 실제 용례 → 대안:
- `frost-induced carbon release` — Feng et al. (2020), *Geoderma* (전문검색 87건)
- `carbon release during freeze–thaw` — Wang et al. (2021), *SBB* (전문검색 210건)

**제안:** `carbon liberation by frost` → `frost-induced carbon release`
```

**검색 불가:**
```markdown
#### 4. `...` — ❓ 검색 불가 — 수동 확인 필요
(API/네트워크 오류로 판정 보류. 재시도하려면 "4번 다시".)
```

### 판정 라벨 (표준 어휘 — 전 출력 동일)
| 라벨 | 의미 | 기준(기본값, `search_strategy.md` §2에서 조정) |
|---|---|---|
| ✅ 확인 | 표준적으로 쓰임 | 따옴표검색 학술 정확일치 다수, 또는 전문검색 ≥ 10건 |
| 🔶 제한적 | 쓰이나 드묾 | 따옴표검색 정확일치 1~2건, 또는 전문검색 1~9건 |
| ⚠️ 미확인 | 용례 없음 → 대안 | 따옴표검색 정확일치 0 + 전문검색 0/미상 |
| ❓ 검색불가 | 판정 보류 | 주력 web search 실패 |

> **검색 백엔드 현실:** 정확구절 용례의 주력은 **web search(따옴표 검색)**다.
> OpenAlex 전문검색 건수는 정밀 정량화용인데 **익명 호출은 throttle(503)이 잦다**
> — 무료 API 키를 발급받아 환경변수 `OPENALEX_API_KEY`로 두면 안정적으로 건수가
> 나온다(없어도 web search만으로 확인/미확인 판정은 가능). 건수를 못 얻으면 출력의
> "(전문검색 N건)"은 생략하거나 "(웹 정확일치 기준)"으로 표기한다. 자세한 건
> `references/search_strategy.md` §1.

## 7. 가드레일 (필수)

- **출처 날조 금지.** 표현을 "확인"으로 판정하려면 **실제 검색 결과에 그 표현이
  존재해야** 한다. 예시 문장·저자·DOI는 검색으로 실제 확인된 것만 인용한다.
- **너무 흔한 표현 처리.** `in this study`, `these results` 같은 초고빈도
  기능구는 변별력이 없다 → "너무 일반적이라 변별 의미 없음"으로 표시하고
  건수만 보고, 대안은 제시하지 않는다.
- **0건 ≠ 절대 오류.** OpenAlex 전문색인은 전체 문헌의 일부다. "미확인"은
  "색인된 코퍼스에서 확인 안 됨"이라는 강한 신호이지 확정 오류가 아니다.
  이 뉘앙스를 미확인 판정에 반드시 담는다.
- **대안도 근거 필수.** NOT FOUND 대안은 반드시 실제 논문에서 attested된
  표현이어야 한다. 근거 없이 "이게 더 자연스러워요"라고 하지 않는다.

## 8. File / Folder 모드 — 원고 순회 점검

붙여넣기 대신 논문 파일/폴더를 점검할 때.

### 8a. 파싱
- 파일: Read → `\n\n` 기준 단락 분리
- 폴더: `ls -1 <폴더>` (Bash) → 파일명으로 섹션 순서 추론 → 시작 섹션 확인

### 8b. 단락 단위 순회
각 단락에 대해 §5(표현 추출 → 병렬 점검 → 렌더링)를 그대로 수행한다.
단락 하나를 끝내면 **여기서 멈추고 사용자 응답을 기다린다.**

**⛔ HARD STOP:** 한 응답에서 **한 단락**까지만 점검한다. 사용자가 "다음 단락"
등으로 명시적으로 응답하기 전에는 다음 단락으로 넘어가지 않는다.

| 사용자 입력 | 처리 |
|---|---|
| "다음 단락" | 다음 단락 점검 |
| "대안 반영해줘" | 이 단락의 미확인 표현을 제안 대안으로 교체 (수정 이력 기록) |
| "N번 자세히" | 해당 표현 추가 예시 검색·상세 |
| "이 섹션 건너뛰기" / "다른 섹션" | 이동 |
| "오늘 여기까지" | §9 세션 요약 후 종료 |

### 8c. 표·그림
- 표/그림 내용 자체는 점검 제외. 캡션은 문장으로 취급해 점검.
