# CHANGELOG — meta-writing-mapping

## 1.1.0 (2026-08-22)

**전체·부분 mapping과 구조 승인 절차를 하나의 계층형 지도에 통합.** 기존
`outline.md`는 단락 순서, 논리 간선, 근거 착지, Ledger, 미해결을 한 문서에
저장했지만 사용자가 어느 결정을 먼저 검토해야 하는지와 해결 항목을 어떻게
은퇴시킬지는 규정하지 않았다. 이번 판은 `outline.md`를 단일 원본으로 유지하면서
범위 투영, 결정 대기열, 상태 생명주기와 자동 파생 뷰를 추가한다.

### 핵심 변경

1. **계층형 부분 mapping**
   - manuscript / section / subsection / paragraph-group을 같은 지도에서 확대·축소
   - 대상 범위의 predecessor·successor를 경계 노드로 한 단계 포함
   - 전체 지도가 없으면 `provisional` 국소 지도를 허용하고 나중에 병합
   - 부분 변경은 범위 밖을 조용히 수정하지 않고 관련 결정을 `reopened`

2. **추천 중심 승인**
   - 완성 outline 전체 승인을 요구하지 않음
   - 모든 질문은 추천·근거·대안 비용·영향·짧은 판정 선택지를 포함
   - 한 번에 최고 우선순위 결정 하나만 질문
   - 저위험·가역 결정은 provisional로 진행하고 예외만 사용자에게 확인

3. **미해결 생명주기**
   - 안정적 `D-###` ID; 결번 허용, 재번호화 금지
   - `detected → surfaced → decided → resolved`, `deferred`, `superseded`,
     `reopened` 상태 도입
   - resolved·superseded는 기록에 남되 활성 대기열에서 제외

4. **outline 형식 1.1**
   - 원고 전체에서 유일한 계층형 단락 ID
   - 다중 predecessor와 논리관계
   - 근거·Ledger의 역할(`first-report`, `supporting`, `interpretation` 등)
   - 원고별 사용자 정의 축
   - 근거·Ledger 인벤토리와 결정 대장
   - 자유문은 `메모`로 보존하되 자동 검증 관계와 분리

5. **자동 파생 도구**
   - `scripts/outline_map.py lint`: 깨진 참조, 근거·Ledger 미배정, first-report
     중복·누락, omitted-only 착지 검출
   - `queue --scope`: 전체 또는 부분 범위의 결정 대기열 생성
   - `dashboard`: 결정 대기열·논리 그래프·근거 매트릭스·검증·해소 기록을
     담은 독립 HTML 생성
   - 구형 6열·세로 outline의 best-effort 읽기와 legacy 경고

### 검증

회귀 테스트 16개를 추가했다. 구조형 파싱, 부분 범위 경계 노드, provisional
외부 연결, 상위 blocker와 downstream reopened 결정, 범위 밖 경고 필터링,
미배정 인벤토리, first-report 중복, 구형 미해결 은퇴, 독립 HTML 생성을 확인한다.

### 구형 파서 결함 넷 — 병합 전 수정

최초 패키지는 합성 fixture로만 검증했다. 실사용 원고(7소절 19단락, Ledger 20건,
미해결 15건)에 걸어보니 `nodes=2 decisions=0 errors=0`이 나왔다. 오류 없이
조용히 통과했고, 대시보드는 단락 0개짜리 멀쩡한 HTML을 냈다. 1.0.2가 "읽는 파일이
검사 보고서면 출력도 검사 보고서가 된다"고 적었듯, **틀렸는데 맞아 보이는 산출물이
가장 비싸다.** 병합 전에 넷을 고쳤다.

1. **legacy 폴백이 오탐에 막혔다.** 폴백 조건이 `if not out.nodes`인데, 1.1 파서가
   `## 구성` 아래의 산문 소제목(`#### 구조 원리` 등)을 단락 노드로 삼았다. 가짜 노드
   둘이 폴백을 막아 본문 전체가 사라졌다. → `_is_structured()` 도입. 포맷 버전 선언이
   있거나 노드가 구조 필드를 실제로 채웠을 때만 1.1로 본다. 폴백 시 껍데기 노드는 버린다.
2. **단락 파서가 `## 구성` 영역에만 묶여 있었다.** 실사용 파일은 단락을 사용자가 지은
   `## 제1부`·`## 제2부` 아래에 둔다. 규격이 그것을 금지한 적이 없고 원칙 7이 오히려
   허용한다. → 허용 목록을 제외 목록(`NON_COMPOSITION_AREAS`)으로 뒤집었다. 이름을
   규격이 정하는 쪽은 메타 영역뿐이기 때문이다.
3. **숫자로 시작하는 이어진 줄이 유령 결정이 됐다.** 미해결 항목 #6의 둘째 줄
   `3장 전반에 깔린다`가 결정 3번으로 잡혀 진짜 #3과 ID가 충돌했다. 번호가 안 겹치면
   경고 없이 유령이 하나 생긴다. → `LEGACY_DECISION`을 열 0 고정으로 바꾸고 번호 뒤
   `.`/`)` 또는 앞 `#`을 요구한다.
4. **한 줄 논지를 다음 줄에 두는 방언에서 논지가 비었다.** 규격은 "논지가 없으면 그
   단락은 아직 설계되지 않은 것"이라고 규정하므로 이는 결과가 따르는 오진이다.
   → P 줄에서 논지를 못 얻으면 이어지는 첫 자유문 줄에서 회수한다.

수정 후 같은 파일이 `nodes=19 decisions=15 errors=0`으로 읽힌다. 소절 분포
(3+5+3 / 3+2+2 / 1)가 원고가 스스로 적어둔 수치와 일치한다.

`tests/fixtures/legacy-real-world.md`를 골든 픽스처로 추가했다. 네 결함을 모두
재현하는 배치이며 내용은 중립 placeholder다 — 실제 원고는 미출판이라 공개 저장소에
넣지 않았다.

### 호환성

기존 `outline.md`를 자동으로 덮어쓰지 않는다. 구형 파일은 읽고 경고하며,
형식 1.1로의 변환은 사용자가 승인한 뒤 수행한다. HTML과 JSON은 언제나 파생물이다.

## 1.0.2 (2026-07-29)

**실사용 검증을 거친 첫 판본.** 1.0.1이 "남은 것"으로 적어둔 검증을 실제로
돌리고, 거기서 드러난 결함 하나를 고쳤다.

### 검증 방법

실제 원고 폴더 두 곳의 사본으로 신선한 문맥의 에이전트 7개를 돌렸다.
각각 "구성 좀 같이 보자" 한 마디를 받고 **첫 응답**을 작성했다.

- A(초고 있음): 완성 투고본 + 그림 7 + 표 2 + 원자료 — 스킬 3회, 대조군 1회
- B(재료만): 계획 문서 3종 + Knowledge 13편 + 그림 2 — 스킬 2회, 대조군 1회

### 결과

스킬 적용 5회가 원칙 ①(모드 안 묻기) ②(본 것 먼저) ③(규칙 이름) ④(표 자제)를
**전부 지켰고, 응답 형태가 수렴했다** — 폴더 요약 → 중심 지목 → 규칙 이름 붙인
지적 3개 → 결정적 질문 하나.

대조군 2회는 **둘 다 3지 선다 메뉴로 끝냈고 규칙 이름을 대지 않았다.**
A 대조군은 첫머리에 9행 표까지 꺼냈다. 원칙 ①③④가 겨냥한 성향이 실재함이
확인됐으므로 이 규칙들은 과잉이 아니다.

### 고친 것 — 3개 상한의 배출구

3회가 서로 다른 방식으로 상한과 씨름했다. 두 번은 4번째 지적을 **괄호에 끼워
넣었고**, 한 번은 규칙에 없는 처리를 지어냈다("일단 적어만 두고 넘어가겠습니다").
규칙이 지켜진 게 아니라 협상된 것이다. 원인은 *말하지 말라*고만 하고 *어디에
두라*고 하지 않은 것.

실제 손해도 확인됐다. 대조군은 원자료를 재계산해 §2.3.1의 "22 such areas"가
21이어야 함을 찾았는데, 스킬 3회는 셋 다 이를 올리지 못했다 — 3개 칸이 이미
찼기 때문이다.

→ `rule-routing.md`: 4번째부터는 버리지 말고 `outline.md` 미해결에 적고,
   적었다는 사실을 한 줄로 알린다. 괄호에 끼워 넣거나 얼버무리는 우회를 금지.
   **상한은 지금 말할 것의 개수이지 찾을 것의 개수가 아니다.**
→ `outline-format.md` 미해결 칸, `structural-integrity.md` 발화 규칙도 맞췄다.

### 아직 확인 못 한 것

첫 응답 한 턴만 봤다. 원칙 ⑤(저장 전 확인) ⑦(사용자 판단 우선), 그리고
원칙 ④의 진짜 시험대 — 대화가 길어졌을 때 표를 꺼내는가 — 는 미검증.
압박 조건(시간·매몰비용)도 걸지 않았다. 대조군 2회는 권장치(5회) 미달.

## 1.0.0 (2026-07-25)

신설. 기존 스킬 어디에도 없던 자리를 메운다 — **집필 전에 섹션·단락 배치를
사용자와 논의하는 단계**.

### 왜 만들었나

기존 스킬을 훑은 결과 구성 매핑 기능은 조각으로만 존재했다.

| 있던 것 | 한계 |
|---|---|
| `meta-writing` Loop 5-0 "골격 확정" | 한 섹션 안에서만, 집필 파이프라인 내부 단계라 산출물로 안 나옴 |
| `meta-writing` `section_guides.md` "구조" 블록 | 일반 템플릿이지 이번 원고의 논지가 아님 |
| `extraction-logic` | 방향이 반대 — 이미 출판된 남의 논문 해부용 |
| `meta-report-writing` Mode C | 한국어 정책보고서 전용, 장·절 단위라 단락 단위가 아님 |

### 설계 결정

1. **양방향, 같은 표.** 재료만 있는 백지 상태와 이미 쓴 초고 둘 다 입력으로
   받고, 출력은 동일한 구성 표다. 형식이 하나라 "설계도 vs 실제 초고" 대조가
   덤으로 따라온다.
2. **모드를 묻지 않는다.** 초안 유무·전체/섹션은 폴더를 보면 알 수 있다.
   사용자에게 선언을 요구하는 순간 대화가 부자연스러워진다는 판단.
3. **단일 `outline.md`.** 섹션별로 쪼개면 전체 조망 때 서로 모순되기 쉽다.
   섹션 진입으로 들어와도 전체 Core message를 자동으로 알게 되는 이점도 있다.
4. **자료는 전부 정독하고, 결과를 근거 노트로 남긴다.** 재조망 때 원자료를
   다시 읽지 않고, `meta-writing`에 Knowledge 소스로 넘기면 그쪽 Loop 2–3도
   생략된다.
5. **표는 6열** — 단락 / 기능 / 한 줄 논지 / ←앞 단락 논리관계 / 근거 /
   Core message 기여. `meta-writing` Loop 5-0의 4열에 기능 태그와 논리관계를
   더했다. 이 둘이 없으면 "P2→P3 논리 단절" 판정 자체가 불가능하다.
6. **태그 어휘는 `extraction-logic` 것을 그대로.** 기능 태그 30개 + 논리관계
   10개. 남의 논문을 해부할 때 쓰던 언어와 내 설계도의 언어가 같아지므로
   "이 논문처럼 배치하기"가 가능해진다.
7. **경계: 설계 = 재료 조달 + 배치, 집필 = 산문화.** 근거 없는 단락은 집필
   결함이 아니라 설계 결함이므로 이 단계에서 웹 검색 보완까지 하고, 그래도
   없으면 단락 삭제나 범위 축소를 제안한다.
8. **`meta-writing`은 손대지 않았다.** 사용자 결정. 대신 `outline.md`를
   Knowledge 경로로 넘기는 방식으로 연동한다.

### 규칙은 새로 쓰지 않았다
