# CHANGELOG — meta-writing-mapping

## 1.0.0 (2026-07-25)

신설. 기존 스킬 어디에도 없던 자리를 메운다 — **집필 전에 섹션·단락 배치를
사용자와 논의하는 단계**.

### 왜 만들었나

기존 스킬을 훑은 결과 구성 매핑 기능은 조각으로만 존재했다.

| 있던 것 | 한계 |
|---|---|
| `meta-writing` Loop 5-0 "골격 확정" | 한 섹션 안에서만, 집필 파이프라인 내부 단계라 산출물로 안 나옴 |
| `meta-writing` `section_guides.md` "구조" 블록 | 일반 템플릿이지 이번 원고의 논지가 아님 |
| `extraction-logic` | 방향이 반대 — 이미 출판된 남의 논문 해부용 |
| `meta-report-writing` Mode C | 한국어 정책보고서 전용, 장·절 단위라 단락 단위가 아님 |

### 설계 결정

1. **양방향, 같은 표.** 재료만 있는 백지 상태와 이미 쓴 초고 둘 다 입력으로
   받고, 출력은 동일한 구성 표다. 형식이 하나라 "설계도 vs 실제 초고" 대조가
   덤으로 따라온다.
2. **모드를 묻지 않는다.** 초안 유무·전체/섹션은 폴더를 보면 알 수 있다.
   사용자에게 선언을 요구하는 순간 대화가 부자연스러워진다는 판단.
3. **단일 `outline.md`.** 섹션별로 쪼개면 전체 조망 때 서로 모순되기 쉽다.
   섹션 진입으로 들어와도 전체 Core message를 자동으로 알게 되는 이점도 있다.
4. **자료는 전부 정독하고, 결과를 근거 노트로 남긴다.** 재조망 때 원자료를
   다시 읽지 않고, `meta-writing`에 Knowledge 소스로 넘기면 그쪽 Loop 2–3도
   생략된다.
5. **표는 6열** — 단락 / 기능 / 한 줄 논지 / ←앞 단락 논리관계 / 근거 /
   Core message 기여. `meta-writing` Loop 5-0의 4열에 기능 태그와 논리관계를
   더했다. 이 둘이 없으면 "P2→P3 논리 단절" 판정 자체가 불가능하다.
6. **태그 어휘는 `extraction-logic` 것을 그대로.** 기능 태그 30개 + 논리관계
   10개. 남의 논문을 해부할 때 쓰던 언어와 내 설계도의 언어가 같아지므로
   "이 논문처럼 배치하기"가 가능해진다.
7. **경계: 설계 = 재료 조달 + 배치, 집필 = 산문화.** 근거 없는 단락은 집필
   결함이 아니라 설계 결함이므로 이 단계에서 웹 검색 보완까지 하고, 그래도
   없으면 단락 삭제나 범위 축소를 제안한다.
8. **`meta-writing`은 손대지 않았다.** 사용자 결정. 대신 `outline.md`를
   Knowledge 경로로 넘기는 방식으로 연동한다.

### 규칙은 새로 쓰지 않았다

판정 근거는 전부 기존 스킬에서 가져왔다(`references/rule-routing.md`가 라우팅).
`structural-integrity.md`와 `section-checklists.md`는 로컬 설치본에 없어
사본으로 번들했다 — 로컬이 최신화되면 사본 대신 원본을 가리키도록 고칠 것.
