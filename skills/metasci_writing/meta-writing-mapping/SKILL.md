# meta-writing-mapping — 글의 지도 그리기

글을 쓰기 전에, 또는 쓰다가 막혔을 때, **글의 설계도(지도)를 사용자와 함께
정한다.** 문장은 쓰지 않는다. 지도는 표 하나와 화살표 그림 하나 — 각 부분의
역할, 하고 싶은 말, 쓸 그림·표·문헌, 앞뒤 연결만 담는다. 단락 내부를 어떻게
풀어쓸지는 `meta-writing` 몫이다.

글쓰기 어느 단계에서든 쓴다. 원고 전체 목차를 잡을 때도, 방법론 섹션 하나의
단락 배치만 잡을 때도 같은 방식이다. 전체 지도가 먼저 있어야 한다는 조건은
없다.

## 하는 일 / 안 하는 일

| 한다 | 안 한다 |
|---|---|
| 섹션·단락의 역할, 순서, 연결을 표+그림으로 설계 | 본문 문장 작성 → `meta-writing` |
| 그림·표·문헌을 어느 부분에 쓸지 배정 | 문장 교정 → `meta-proofreading` |
| 구조 문제를 찾아 함께 결론 냄 | 단락 재작성 → `meta-rewriting` |
| 합의된 지도를 `outline.md`로 저장 | 문체 손질 → `meta-styling` |

## 지도 형식

작업 폴더의 `outline.md` 한 파일. 그림 한 줄 + 표 하나가 기본형이고, 크기에
따라 행의 단위만 달라진다.

| 보는 크기 | 표의 한 행 |
|---|---|
| 글 전체 | 섹션 (Intro, Methods, R3.1 …) |
| 섹션 하나 | 단락 (예정 단락 하나 또는 묶음) |

### 예시 — 방법론 섹션의 단락 배치만 잡을 때

```markdown
# 지도 — Methods 단락 구성

(앞: Intro가 연구 질문을 던짐)
M1 → M2 → M3 → M4
(뒤: R3.1이 첫 결과를 보고함)

| 단락 | 역할 | 하고 싶은 말 | 쓸 자료 | 다음으로 |
|---|---|---|---|---|
| M1 | 연구 지역 | 4대강 유역 34개 지점을 대상으로 했다 | Fig-1(지도) | 이어서 |
| M2 | 시료·분석 | 월 1회 채취, ICP-MS로 분석했다 | Table-1 | 이어서 |
| M3 | 산정 방법 | ABL은 부하량-유량 회귀로 산정했다 | 식(1), Kim2023 | 그래서 |
| M4 | 통계 | 유역 간 차이는 Kruskal-Wallis로 검정 | ⚠ 자료없음 | — |
```

### 예시 — 글 전체를 잡을 때

```markdown
# 지도 — 원고 전체
이 글의 주장: 유역 단위 ABL 차이가 국가 단일값 관리의 한계를 보여준다

Intro ─질문→ Methods → R3.1 ─대조→ R3.4 ─질문→답→ D4.2 → 결론

| 섹션 | 역할 | 하고 싶은 말 | 쓸 자료 | 다음으로 |
|---|---|---|---|---|
| Intro | 질문 제기 | 국가 단일값은 유역 차이를 놓친다 | Chen2024 | 질문 던짐 |
| Methods | 산정 방법 | 유역 단위 ABL 산정 절차 | Fig-1, 식(1) | 이어서 |
| R3.1 | 전국 개관 | 전국 평균 ABL은 안정적이다 | Fig-2, Table-1 | 대조 |
| R3.4 | 유역 차이 | 유역 간 차이 크고 예외 유역 존재 | Fig-4, Table-S2 | 질문→답 |
| D4.2 | 예외 해석 | 예외는 축산 활동으로 설명된다 | Chen2024 | 그래서 |
| 결론 | 답과 함의 | 관리 단위를 유역으로 내려야 한다 | — | — |
```

형식 규칙:

- 열은 다섯 개로 고정 — **단위 · 역할 · 하고 싶은 말 · 쓸 자료 · 다음으로**.
  다른 열이나 필드를 만들지 않는다.
- "하고 싶은 말"은 화제("~에 대하여")가 아니라 주장 한 문장.
- 쓸 자료가 없으면 지어내지 말고 `⚠ 자료없음` — 어떻게 할지(삭제 / 자료 요청 /
  주장 축소)를 ◇로 올린다.
- 부분만 그릴 때는 앞뒤 이웃을 `(앞: …)` `(뒤: …)` 한 줄씩만 적는다. 전체
  지도나 초고가 없어 추측이면 `(앞: … — 추정)`으로 표시한다.
- 섹션 지도는 논의하는 섹션 것만 만든다. 전부 미리 채우지 않는다.
- 체크리스트의 세부 요구(예: 통계 서술에 들어갈 항목들)는 표에 욱여넣지
  않는다. 지도는 배치까지만 정하고, 세부는 마무리 단계의 집필 주의사항으로
  `meta-writing`에 전달한다.

## 말 규칙

지도와 대화에 쓰는 말은 아래로 고정한다. 새 용어를 만들지 않는다.

- 연결어: **이어서 · 대조 · 그래서 · 왜냐하면 · 예를 들어 · 질문→답 · 질문 던짐**
- 정할 것 표시: **◇** / 자료 빈 곳: **⚠ 자료없음** / 이번에 바뀐 행: **`*`**
- 부분 이름은 항상 내용과 함께 부른다 — "M3(산정 방법)", "Fig-4(유역 지도)".
- 금지: 영어 기능 태그(Comparison, Gap …), 그래프 용어(노드, 간선, 경계),
  관리 용어(blocker, provisional, Ledger, first-report). 개념이 필요하면
  일상어로 풀어 말한다.

## 진행 방식

1. **자료 읽기** — 작업 폴더의 초고(.docx/.md/.tex), `figures/`, `tables/`,
   `knowledge/`, `pdf/`, 기존 `outline.md`. 무엇을 보고 판단했는지 한 줄로 밝힌다.
2. **초안 지도를 한 번에 제시** — 절반짜리를 내밀고 묻지 않는다. 그림 + 표
   완성본을 만들고, 판단 근거(참고 파일)를 먼저 읽는다.
3. **◇ 정할 것 표시** — 모델이 확신 없는 지점만 지도에 ◇를 달고, 표 아래에
   각각 한 줄 양자택일로 묻는다. 최대 3개. 확신 있는 부분은 묻지 않는다.
   ```text
   ◇ Fig-4를 R3.4에 둘까, D4.2로 옮길까 — 결과로 보이면 R3.4, 해석 도구면 D4.2
   ```
4. **라운드** — 사용자가 지적하면 그 부분을 고쳐 **지도 전체를 다시 제시**한다.
   바뀐 행에 `*`. 부분 답장으로 흩어놓지 않는다.
5. **저장** — 합의되면 `outline.md`로 저장한다. 처음 만들 때는 저장 전에 묻고,
   사용자가 수정을 지시한 경우는 바로 반영하고 보고한다.
6. **마무리 — 독자 흐름 확인** — 확정된 지도를 독자가 읽는 순서대로 짧은 산문
   한 단락으로 풀어 보여주고 "이렇게 읽히는 게 맞습니까"를 확인한다. 이어서
   심사자가 걸고넘어질 구조 약점을 최대 3개 짚는다. 치명적이지 않으면 확정을
   막지 말고 집필 단계 주의사항으로 남긴다.

## 판단 기준과 말하는 법

지도 초안을 만들거나 문제를 짚기 전에 읽는다:

- `references/section-checklists.md` — 이 섹션에 어떤 부분이 있어야 하나
  (섹션 안). 논의 중인 섹션 항목만 읽는다. ★ 항목을 먼저 꺼낸다.
- `references/structural-integrity.md` — 한쪽에서 약속한 것을 다른 쪽이
  지켰나 (섹션 사이). 양쪽이 다 있을 때만 판정한다.

말하는 법:

- 문제는 **왜 문제인지 + 어떻게 되는지 한 줄**로. 진단 태그를 붙인 보고서
  양식이 아니라 대화로 말한다.
  - 좋음: "서론은 급감의 원인을 묻는데 논의는 영향에 답합니다. 어느 쪽이
    이 글의 질문입니까?"
  - 나쁨: "**[질문 사슬 불일치]** 서론의 연구 질문은 [A]인데…"
- 한 응답에 ◇ 질문과 문제 지적을 **합쳐서 최대 3개**. 나머지는 다음 라운드로.
- 의도일 수 있는 것(순서 차이 등)은 단정하지 말고 묻는다.
- 사용자 판단과 충돌하면 근거를 대고 한 번 반대한다. 재확인하면 따른다.

## 완료 기준

- 지도의 모든 행에 역할·하고 싶은 말·쓸 자료(또는 ⚠ 처리 방향)·연결이 채워짐
- ◇가 남아 있지 않음
- `outline.md` 저장됨
- 독자 흐름 확인을 통과함
- 심사자 관점 약점이 전달됨

집필로 넘어갈 때: 해당 섹션의 표 한 장이 `meta-writing`의 입력이 된다.
