# 구조 결정 프로토콜

mapping 결과를 사용자가 검토 가능한 작은 결정으로 바꾼다. 완성 outline 전체를
한꺼번에 승인받지 않는다.

## 1. 승인 원칙

모델이 가능한 안을 비교하고 최선안을 먼저 추천한다. 사용자는 구조를 처음부터
설계하는 사람이 아니라 추천안의 예외를 결정하는 최종 저자다.

모든 질문은 다섯 요소를 가진다.

1. 무엇을 결정하는가
2. 추천안은 무엇인가
3. 추천 이유는 무엇인가
4. 다른 안을 택하면 무엇이 달라지는가
5. 어떤 짧은 응답으로 결정할 수 있는가

```text
[D-021 · high · RESULTS.3.4] Table-S2의 최초 보고 위치

추천: P1에서 전체 분포와 함께 처음 보고하고 P2·P3에서는 참조만 한다.
근거: P1이 소절의 결과 진입점이고 P2·P3은 각각 변동과 예외를 확대한다.
대안의 비용: P2에서 처음 보고하면 P1의 핵심 주장이 직접 근거 없이 시작한다.
영향: RESULTS.3.4.P1–P3, DISCUSSION.4.2.P1

판정: 추천 채택 / P2에서 최초 보고 / 부분 수정 / 보류
```

개방형 질문만 던지지 않는다. 추천을 만들 수 없을 만큼 자료가 부족하면 부족한
증거를 특정하고 자료 한 가지를 요청한다.

## 2. 결정 순서

전체 mapping:

1. Core message
2. 독자의 전체 이동 경로
3. 섹션 존재·순서·경계
4. 섹션별 단락 묶음
5. 단락별 기능·한 줄 논지
6. 근거·Ledger 착지
7. 경계 간선
8. 기계적 항목

부분 mapping:

1. 대상 범위를 막는 상위 blocker
2. 들어오는 간선과 나가는 간선
3. 내부 단락 사슬
4. 근거·Ledger 착지
5. 범위 밖 파급 결정
6. 기계적 항목

상위 결정이 미확정이어도 되돌리기 쉬운 하위 결정은 `provisional`로 진행할 수
있다. 다만 `resolved`라고 부르지 않는다.

## 3. 반드시 묻는 것 / 임시 진행하는 것

### 반드시 묻는다

- Core message
- 섹션의 존재·삭제·병합
- Results와 Discussion의 경계
- 원고 범위를 넓히거나 줄이는 결정
- 근거가 둘 이상의 해석을 허용하는 핵심 주장
- 여러 섹션 또는 3개 이상 단락에 영향을 주는 배치
- 사용자의 기존 판단과 충돌하는 변경

### 추천안으로 임시 진행할 수 있다

- 명백한 중복 단락 통합
- 같은 기능 단락의 경미한 순서 조정
- 기능 태그·논리관계 표기 정규화
- 근거 역할 `supporting/reference` 구분
- 쉽게 되돌릴 수 있는 국소 배치

자동 진행 항목은 `provisional`로 기록하고 현재 범위 마무리 때 요약한다.

## 4. 우선순위

`blocker → high → medium → low → mechanical` 순이다. 같은 우선순위에서는
영향 섹션·단락 수, 후속 의존 결정 수, 근거 불확실성, 되돌리기 비용을 본다.
점수를 보여줄 필요는 없지만 왜 먼저 결정해야 하는지는 한 문장으로 설명한다.

## 5. 범위별 대기열

부분 mapping에서 전체 결정 목록을 보여주지 않는다. 현재 대기열에는 다음만 둔다.

- 현재 범위의 조상을 막는 blocker
- 현재 범위 내부 활성 결정
- 현재 범위 변경으로 직접 영향을 받는 범위 밖 결정

관련 없는 다른 섹션의 low·mechanical 항목은 숨긴다.

## 6. 상태 전환

```text
detected → surfaced → decided → resolved
                    ↘ deferred
어느 상태에서든 → superseded
resolved/deferred → reopened
```

- `detected → surfaced`: 추천·근거·대안 비용을 갖춘 카드로 제시
- `surfaced → decided`: 사용자가 채택·대안·부분 수정을 선택
- `decided → resolved`: outline 반영과 참조·영향 검증 완료
- `surfaced/decided → deferred`: 지금 결정하지 않기로 함
- `* → superseded`: 다른 결정이 문제를 대체
- `resolved/deferred → reopened`: 상위 결정·범위·근거 변경으로 기존 판단 재검토

`resolved`는 단순 동의가 아니라 파일 반영과 영향 검증까지 끝난 상태다.

## 7. 영향 전파

부분 범위 안 변경이 바깥에 영향을 주면 자동 수정하지 않는다.

```text
현재 변경: RESULTS.3.4.P2와 P3 순서 교환
범위 밖 영향: DISCUSSION.4.2.P1–P2가 기존 결과 순서를 따름
처리: 관련 결정 D-028을 reopened
```

영향받는 결정이 없으면 새 ID를 만든다. 단순 알림으로 끝내지 않는다.

## 8. 범위 종료

한 범위의 논의는 다음으로 닫는다.

1. 이번에 resolved된 결정
2. provisional로 진행한 결정
3. deferred/reopened로 남은 결정
4. 범위 밖 파급
5. 압축 모의 독해

모의 독해는 표가 아니라 독자가 따라갈 주장 사슬을 짧은 산문으로 보여준다.

```text
이 소절은 먼저 유역별 ABL 분포를 보고하고, 이어 변동 폭을 비교한 뒤 예외 유역을
분리한다. 다음 Discussion은 이 예외가 토지이용과 축산활동으로 어디까지 설명되는지
검토한다.
```

사용자에게 실제 질문과 일치하는지, 빠진 핵심이 있는지, 과도한 강조가 있는지만
확인한다.

## 9. 최종 반대 검토

확정 전에 반대 심사자 관점의 구조 위험을 최대 3개만 제시한다.

- 근거보다 넓은 주장
- 던지고 받지 않은 질문
- 같은 근거의 중복 first-report
- Results와 Discussion 중복
- 부분 변경으로 생긴 범위 밖 불일치

치명적이지 않으면 확정을 막지 말고 집필 단계 주의사항으로 분리한다.
